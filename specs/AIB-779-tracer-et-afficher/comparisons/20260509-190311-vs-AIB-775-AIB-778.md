## Implementation Choices Analysis

### [Spec] Surface in same zone as execution metrics
| Ticket | Approach |
|--------|----------|
| AIB-779 | Adds `Plugin` + `Agent CLI` rows inside the existing details grid; expands panel even when no token telemetry exists. |
| AIB-775 | Adds `Plugin Version` + `CLI Version` rows inside the details grid; also removes the `canExpand` gating (behaviour change). |
| AIB-778 | Renders versions as **header badges** next to the model badge — outside the expanded execution-metrics panel. |

**Best**: AIB-779 — meets the spec without altering pre-existing collapse behaviour.

### [Spec] Discrete placeholder when absent
| Ticket | Approach |
|--------|----------|
| AIB-779 | Em-dash inside expanded panel; only visible when user expands. |
| AIB-775 | Em-dash inside expanded panel; tooltip "Non disponible". |
| AIB-778 | Hyphen `-` always visible in header bar even for legacy jobs — not discrete. |

### Decision Point: Capture transport
| Ticket | Approach | Trade-offs |
|--------|----------|-----------|
| AIB-779 | Reuses `PATCH /jobs/:id/status` + idempotent RUNNING path | Single endpoint, minimal API surface, runner emits one extra curl per agent |
| AIB-775 | New `POST /jobs/:id/versions` endpoint with first-write-wins via `updateMany` | Clean isolation but more API surface; capture script also re-installs CLIs (duplicates `install_*` in run-agent) |
| AIB-778 | run-agent.sh exports `PLUGIN_VERSION`/`AGENT_CLI_VERSION` to `$GITHUB_ENV`; separate workflow step PATCHes `/status` | Splits logic across shell + YAML; brittle env-var passing |

**Best**: AIB-779 — least new surface, leverages existing schema and validator extensions cleanly.

### Decision Point: Server-side write semantics
| Ticket | Approach | Constitution |
|--------|----------|--------------|
| AIB-779 | Helper `buildVersionPatch()` shared by initial + idempotent RUNNING handlers; single Prisma update per request | Yes |
| AIB-775 | Conditional `prisma.updateMany({ where: { id, pluginVersion: null } })` — race-safe at DB layer | Yes |
| AIB-778 | Inline `if (... && !job.pluginVersion)` checks in the main update path only | Yes (race window narrower) |

### Decision Point: Migration column sizing
| Ticket | pluginVersion | agentCliVersion |
|--------|---------------|-----------------|
| AIB-779 | VARCHAR(50) | VARCHAR(100) |
| AIB-775 | VARCHAR(100) | VARCHAR(100) |
| AIB-778 | VARCHAR(40) | VARCHAR(40) |

**Note**: AIB-778's 40-char limit may truncate verbose CLI strings (e.g. `gemini --version` multi-token output).

## Ranking & Recommendation

### 1. **AIB-779** — Best code (94%)
**Why it wins**:
- 100% spec fulfilment with versions rendered exactly where the spec requires.
- Reuses `PATCH /status` instead of inventing a new endpoint or YAML plumbing.
- Idempotent-RUNNING backfill path is a thoughtful detail other implementations skipped.
- Strong unit coverage on the new shell helpers (`run-agent-version-capture.test.ts`).

### 2. **AIB-775** — (90%)
**Why it lost**:
- Adds a new endpoint + extra capture script that re-installs each CLI before run-agent does — duplicate work.
- Removes the `canExpand` gate, changing prior collapse behaviour for non-telemetry jobs.

### 3. **AIB-778** — (82%)
**Why it lost**:
- Versions rendered as header badges, not in the execution-metrics zone (spec violation).
- Hyphen placeholder always visible, not discrete.
- VARCHAR(40) risks truncation for some CLIs.
- Capture/PATCH split between bash and YAML adds moving parts.
