## Implementation Choices Analysis

### [Spec] Replace duplicated workflow setup blocks
| Ticket | Approach |
|--------|----------|
| AIB-468 | Modifies all 6 workflows (speckit, quick-impl, verify, iterate, health-scan, ai-board-assist) to call setup-environment.sh, removing 200+ lines of duplication |
| AIB-450 | Only creates the script; no workflow files are modified |

**Best**: AIB-468 - This is the core deliverable of the ticket. Without workflow integration, the script is unused.

### [Spec] Project dependency detection (Prisma/Playwright)
| Ticket | Approach |
|--------|----------|
| AIB-468 | Detects Prisma and Playwright via package.json/config files, sets HAS_PRISMA/HAS_PLAYWRIGHT env vars, runs prisma generate |
| AIB-450 | No dependency detection; workflows would still need inline detection steps |

**Best**: AIB-468 - Centralizes dependency detection that was previously duplicated across workflows.

### [Spec] .ai-board/config.yml creation
| Ticket | Approach |
|--------|----------|
| AIB-468 | Creates config.yml for the ai-board project itself (29 lines) |
| AIB-450 | No config file created; tests use fixture configs only |

**Best**: AIB-468 - The project needs its own config.yml to work with the script.
