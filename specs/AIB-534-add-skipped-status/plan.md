# Implementation Plan: Add SKIPPED Status for Health Scans

**Branch**: `AIB-534-add-skipped-status` | **Date**: 2026-04-04 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/AIB-534-add-skipped-status/spec.md`

## Summary

Add a `SKIPPED` terminal status to the health scan lifecycle for scans that find nothing to evaluate. This eliminates false-positive "score 100" results for empty scans (e.g., REVIEW_QUALITY with no PRs, SECURITY with no changed files). The SKIPPED status preserves previous HealthScore aggregates, appears in scan history with distinct visual treatment, and is excluded from trend charts.

## Implementation Phases

### Phase 1: Database — Add SKIPPED Enum Value

**Files**: `prisma/schema.prisma`
**Action**: Add `SKIPPED` to `HealthScanStatus` enum, run `bunx prisma migrate dev`, regenerate client.
**Risk**: Low — additive enum change, no existing data affected.

### Phase 2: API — Status PATCH Endpoint

**File**: `app/api/projects/[projectId]/health/scans/[scanId]/status/route.ts`
**Changes**:
1. Add `'SKIPPED'` to Zod `statusUpdateSchema.status` enum
2. Add `SKIPPED` to `VALID_TRANSITIONS`: PENDING → [..., 'SKIPPED'], RUNNING → [..., 'SKIPPED'], SKIPPED → []
3. Add validation: if `status === 'SKIPPED'` and `score` is provided, return 400
4. Set `completedAt` for SKIPPED (it is a terminal state)
5. In the transaction: skip the HealthScore upsert block when `status === 'SKIPPED'`

### Phase 3: API — Health GET Endpoint

**File**: `app/api/projects/[projectId]/health/route.ts`
**Changes**:
1. Update `latestScans` query filter from `status: 'COMPLETED'` to `status: { in: ['COMPLETED', 'SKIPPED'] }`
2. Update `buildModuleStatus()` to detect `scanStatus === 'SKIPPED'` and set `summary: 'Nothing to evaluate'`
3. Pass latest scan status through to the response so the UI can distinguish SKIPPED

### Phase 4: UI — Module Card

**File**: `components/health/health-module-card.tsx`
**Changes**:
1. Add `'skipped'` to `CardState` union type
2. Update `getCardState()`: if `module.scanStatus === 'SKIPPED'` → return `'skipped'`
3. Update `ScoreBadge`: add `skipped` case rendering "Skipped" in muted styling
4. Update `BUTTON_LABELS`: add `skipped: 'Re-run'`
5. Show previous score if available (from HealthScore aggregate, passed through module.score)

### Phase 5: UI — Drawer States & History

**File**: `components/health/drawer/drawer-states.tsx`
**Changes**:
1. Add `'skipped'` to `DrawerState` type
2. Add `skipped` detection in `getDrawerState()`: if `moduleStatus.scanStatus === 'SKIPPED'` and no report data
3. Add `skipped` case in the switch: "Nothing to evaluate" message with info icon

**File**: `components/health/drawer/drawer-history.tsx`
**Changes**:
1. In `HistoryEntry`: detect `scan.status === 'SKIPPED'` and render a "Skipped" badge instead of score

### Phase 6: Workflow

**File**: `.github/workflows/health-scan.yml`
**Changes**:
1. In the "Merge Scan Outputs" step: check if result JSON contains `status: "SKIPPED"` or `skipped: true`
2. In the "Update Status" step: if SKIPPED, send `{ status: "SKIPPED" }` without score to the PATCH endpoint
3. Skip remediation ticket creation for SKIPPED scans

### Phase 7: Tests

**Extend**: `tests/integration/health/health-score.test.ts`
- Test that GET /health returns correct module status when latest scan is SKIPPED
- Test that global score is unaffected by SKIPPED scans

**Extend**: `tests/unit/components/health-module-card.test.tsx`
- Test `skipped` card state renders "Skipped" badge
- Test that previous score is still displayed

**New**: `tests/integration/health/health-scan-skipped.test.ts`
- Test PENDING → SKIPPED transition succeeds
- Test RUNNING → SKIPPED transition succeeds
- Test SKIPPED → (any) transition returns 409
- Test SKIPPED with score returns 400
- Test SKIPPED does not update HealthScore aggregate
- Test SKIPPED scan appears in scan history
