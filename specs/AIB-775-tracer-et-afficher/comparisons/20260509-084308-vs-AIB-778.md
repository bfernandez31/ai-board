## Implementation Choices Analysis

### [Spec] FR-005 Placement of versions in the job detail panel
| Ticket | Approach |
|--------|----------|
| AIB-775 | Adds two labelled rows ("Plugin Version:", "CLI Version:") inside the existing execution-metrics block, beside model/tokens/duration/cost — exactly the zone the spec calls out. |
| AIB-778 | Adds two unlabelled small badges in the collapsed row header next to the `model` badge; nothing renders in the actual metrics block. |

**Best**: AIB-775 — direct match with spec FR-005 ("dans la même zone que les autres métriques d'exécution").

### [Spec] FR-006 Placeholder + "Non disponible" tooltip
| Ticket | Approach |
|--------|----------|
| AIB-775 | `title={value == null ? 'Non disponible' : undefined}` over an em-dash `-` — both halves of FR-006 covered. |
| AIB-778 | Renders `value ?? '-'` only — no tooltip, no accessible "Non disponible" affordance. |

**Best**: AIB-775 — explicit spec text fulfilled.

### [Spec] Plugin version SHA fallback
| Ticket | Approach |
|--------|----------|
| AIB-775 | Reads `plugin.json#version`; if missing, falls back to `sha:<short>` from the plugin git checkout. |
| AIB-778 | Reads `plugin.json#version` only; logs a skip and emits empty when missing. |

**Best**: AIB-775 — implements the auto-resolved decision in the spec.

### Decision Point 1: Capture transport
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-775 | New `POST /api/jobs/:id/versions` + dedicated `capture-versions.sh` (auth, Zod, retry 1/2/4s, first-write-wins). | Yes (IV. Security: workflow auth, Zod validation) | +1 endpoint and 1 script, but single-purpose & decoupled from job status lifecycle. |
| AIB-778 | Extends `PATCH /api/jobs/:id/status` to accept `pluginVersion`/`agentCliVersion`; capture happens inside `run-agent.sh` and is flushed by a separate workflow step. | Yes (Zod extended) | Reuses existing endpoint but couples versioning to RUNNING transitions and adds branching to a critical runner script. |

**Best**: AIB-775 — single-responsibility endpoint, isolated from status lifecycle, easier to reason about and test.

### Decision Point 2: Failure handling & observability
| Ticket | Approach | Trade-offs |
|--------|----------|------------|
| AIB-775 | Per-phase stderr warnings ("plugin version probe failed", "cli probe failed", "api … after retries") with retry/backoff; script always exits 0. | Honors FR-010 (warning logged) and FR-004 (non-blocking). |
| AIB-778 | `\|\| true` on the curl, no warning emitted, no retry. | Non-blocking (FR-004 met) but FR-010 (warning logged) not implemented. |

**Best**: AIB-775.

### Decision Point 3: Schema column width
| Ticket | Choice | Note |
|--------|--------|------|
| AIB-775 | `VARCHAR(100)` (validator: `min(1).max(100)`) | More headroom for future CLI banners. |
| AIB-778 | `VARCHAR(40)` (validator: `min(1).max(40)`) | Tight — risks truncating multi-word `--version` banners. |

**Best**: AIB-775 — safer ceiling for unknown CLI formats (spec edge case "Format de version reportée par un CLI inconnu / non parsable" requires preserving raw string).

## Ranking & Recommendation

### 1. **AIB-775** — Best code (score: 90%)
**Why it wins**:
- Fully implements FR-005 (placement) and FR-006 (em-dash + "Non disponible" tooltip) — AIB-778 misses both.
- Implements the auto-resolved SHA fallback for plugin version.
- Dedicated capture script with retry/backoff and per-phase warnings (FR-010).
- Clean separation: new single-purpose endpoint, no entanglement with the job-status lifecycle, no edits to `run-agent.sh`.

### 2. **AIB-778** — (score: 72%)
**Why it lost**:
- UI placement diverges from FR-005 (small header badges, not in execution-metrics zone).
- No "Non disponible" tooltip → FR-006 only partially satisfied.
- No SHA fallback when plugin version is absent.
- Capture failure is silent (no warning) — FR-010 missed.
- Pluses (smaller diff, runner unit test, reuses existing endpoint) don't outweigh spec gaps.
