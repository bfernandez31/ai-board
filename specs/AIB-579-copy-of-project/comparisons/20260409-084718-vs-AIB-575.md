## Implementation Choices Analysis

### [Spec] Deterministic stack detection implementation
| Ticket | Approach |
|--------|----------|
| AIB-579 | TypeScript library (`lib/onboarding/detect-stack.ts`) with typed interfaces, Zod-validated output, reusable from workflow scripts and unit tests |
| AIB-575 | 693-line Bash script (`detect-stack.sh`) with shell-level JSON assembly via `jq` |

**Best**: AIB-579 — TypeScript-first per constitution Principle I; testable as a library; type-safe.

### [Spec] Structured callback and artifact summary
| Ticket | Approach |
|--------|----------|
| AIB-579 | Zod-validated `artifactSummarySchema` with typed `created/preserved/missing` arrays and `partialReason`; `superRefine` cross-field validation on status route |
| AIB-575 | Raw JSON built in shell with `jq -n`; simpler flat arrays (paths only, no kind/reason) |

**Best**: AIB-579 — Validates at API boundary per constitution Principle IV; richer artifact metadata.
