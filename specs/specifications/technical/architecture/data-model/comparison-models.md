# Comparison Models

## Comparison Models

Five models store structured comparison data generated by the `/compare` command.

### ComparisonRecord

Root model for a comparison analysis.

**Fields**:
- `id`: Auto-incrementing identifier
- `projectId`: Parent project
- `sourceTicketId`: Ticket that triggered the `/compare` command
- `winnerTicketId`: Ticket recommended as best implementation
- `compareRunKey`: Optional idempotency key for workflow-driven persistence (max 255 chars). Prevents duplicate records on workflow retry.
- `markdownPath`: Path to the markdown report file on the branch
- `summary`: Executive summary (max 2000 chars)
- `overallRecommendation`: Full recommendation text (max 10000 chars)
- `keyDifferentiators`: JSON array of differentiating factors
- `generatedAt`: Timestamp of report generation

**Relationships**:
- Belongs to Project (cascade delete)
- References sourceTicket and winnerTicket (Ticket, cascade delete)
- One-to-many: ComparisonParticipants, DecisionPointEvaluations

**Indexes**:
- `(projectId, generatedAt DESC)`: List comparisons for a project
- `(sourceTicketId, generatedAt DESC)`: Find comparisons by source ticket
- `(winnerTicketId, generatedAt DESC)`: Find comparisons by winner

**Constraints**:
- Unique `(projectId, sourceTicketId, compareRunKey)`: One record per compare run per source ticket

### ComparisonParticipant

Links a compared ticket to a comparison with ranking data.

**Fields**:
- `comparisonRecordId`: Parent comparison
- `ticketId`: Participating ticket
- `rank`: Position in ranking (1 = best)
- `score`: Quality score (0-100)
- `workflowTypeAtComparison`: Snapshot of ticket's workflow type at comparison time
- `agentAtComparison`: Snapshot of ticket's agent at comparison time
- `rankRationale`: Explanation for the assigned rank (max 4000 chars)

**Constraints**:
- Unique `(comparisonRecordId, ticketId)`: A ticket appears once per comparison
- Unique `(comparisonRecordId, rank)`: No tied ranks

**Relationships**:
- One-to-one: TicketMetricSnapshot
- One-to-many: ComplianceAssessments

### TicketMetricSnapshot

Code change metrics snapshot captured at comparison time (1:1 with ComparisonParticipant).

**Fields**:
- `linesAdded`, `linesRemoved`, `linesChanged`, `filesChanged`, `testFilesChanged`: Nullable integers
- `changedFiles`: JSON array of changed file paths
- `bestValueFlags`: JSON object indicating which metrics are best among participants

### DecisionPointEvaluation

Records a key architectural decision and how each ticket approached it.

**Fields**:
- `comparisonRecordId`: Parent comparison
- `title`: Decision point name (max 255 chars)
- `verdictTicketId`: Ticket with the best approach (nullable, SET NULL on ticket delete)
- `verdictSummary`: Short verdict (max 4000 chars)
- `rationale`: Detailed reasoning (max 10000 chars)
- `participantApproaches`: JSON array of `{ ticketId, ticketKey, summary }` per participant
- `displayOrder`: Sort position within the comparison

**Constraints**:
- Unique `(comparisonRecordId, displayOrder)`

### ComplianceAssessment

Per-principle constitution compliance evaluation for a participant.

**Fields**:
- `comparisonParticipantId`: Parent participant
- `principleKey`: Machine-readable principle identifier (max 100 chars)
- `principleName`: Human-readable principle name (max 255 chars)
- `status`: Assessment result (`pass`, `mixed`, `fail`)
- `notes`: Detailed assessment notes (max 4000 chars)
- `displayOrder`: Sort position

**Constraints**:
- Unique `(comparisonParticipantId, principleKey)`: One assessment per principle per participant
