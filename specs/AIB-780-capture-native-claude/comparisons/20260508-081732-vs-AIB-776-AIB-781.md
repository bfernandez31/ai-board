## Implementation Choices Analysis

### [Spec] Non-Claude job → no raw artifact, no error
| Ticket | Approach |
|--------|----------|
| AIB-780 | Runner-side `if [[ "$AGENT_UPPER" == "CLAUDE" ]]` only; PUT endpoint multiplexed via `?type=raw` accepts any agent. |
| AIB-776 | Runner-side guard **plus** dedicated `PUT /logs/artifact-raw` returns 422 `AGENT_NOT_SUPPORTED` for non-CLAUDE jobs. |
| AIB-781 | Runner-side guard only; dedicated `/native-artifact` PUT does no agent check — relies entirely on the runner. |

**Best**: AIB-776 — defence-in-depth. Server enforces what the spec requires, not just the runner.

### [Spec] Raw artifact properly redacted
| Ticket | Approach |
|--------|----------|
| AIB-780 | Exports `deepRedact` from shared `redactor.mjs` and reuses it in the bash node block. Single source of truth. |
| AIB-776 | **Inlines a copy of `deepRedact`** inside the bash `node -e` block (~20 lines duplicated). Will drift from `redactor.mjs`. |
| AIB-781 | Exports `deepRedact` from shared `redactor.mjs` and reuses it. Same approach as AIB-780. |

**Best**: AIB-780 / AIB-781 — single source of truth, no drift risk.

### Decision Point: Endpoint design
| Ticket | Approach | Trade-offs |
|--------|----------|------------|
| AIB-780 | Reuse `PUT /artifact` and `GET /raw` with `?type=raw\|native` query param. | DRY, less surface area, but mixes two artifact contracts in one handler. |
| AIB-776 | New `PUT /logs/artifact-raw` and `GET /logs/raw-native`. | Cleanest separation; each route owns its validation; easier to evolve independently. |
| AIB-781 | New `PUT /logs/native-artifact` and `GET /logs/native`. | Same shape as AIB-776 but no API-level agent guard. |

**Best**: AIB-776 — separation matches the constitution's API-design preference for explicit, single-purpose routes.

### Decision Point: Bash-script structure
| Ticket | Approach |
|--------|----------|
| AIB-780 | Extracts `upload_artifact()`, `read_artifact_key()`, `artifact_size()` helpers — both phases share them. |
| AIB-776 | Phase 5b duplicates the upload retry loop and `read_artifact_key` node block. |
| AIB-781 | Single ad-hoc `curl` call for the native upload, no retry logic at all. |

**Best**: AIB-780 — only ticket that actually refactored the script for reuse. AIB-781 silently regresses on retry semantics for the native path.

### Decision Point: Storage key naming
| Ticket | Suffix |
|--------|--------|
| AIB-780 | `{jobId}-raw.jsonl.gz` |
| AIB-776 | `{jobId}.native.jsonl.gz` |
| AIB-781 | `{jobId}.native.jsonl.gz` |

**Best**: AIB-776 / AIB-781 — `.native` is more precise than `-raw` (which is ambiguous with the existing `/raw` read URL).

### Decision Point: Schema cross-field validation
| Ticket | Approach |
|--------|----------|
| AIB-780 | Adds Zod `.refine()` ensuring `rawArtifactKey` / `rawArtifactSize` are both present or both absent. |
| AIB-776 | Adds the same paired `.refine()` check. |
| AIB-781 | No paired refinement — submission with key but no size (or vice versa) would be silently accepted. |

**Best**: AIB-780 / AIB-776.

## Ranking & Recommendation

### 1. AIB-776 — Best (~89%)
- Only ticket enforcing the CLAUDE-only contract at the API layer (defence in depth).
- Highest test density (544 lines covering PUT happy/sad paths, GET, prune, schema, agent gating).
- CLAUDE.md updated with the new routes and pruning behaviour.
- Trade-off: ~20 lines of `deepRedact` duplicated inline in the bash node block — easy follow-up.

### 2. AIB-780 — Source (~84%)
- Cleanest bash refactor (shared `upload_artifact` / `read_artifact_key` helpers).
- Reuses the shared `deepRedact` — no duplication.
- Multiplexing endpoints via `?type=` is concise but couples two artifact contracts.
- Misses CLAUDE.md update.

### 3. AIB-781 — (~82%)
- Endpoint shape is fine but no API-level CLAUDE check; relies entirely on the runner.
- Native upload path has no retry loop, regressing the resilience the normalized path enjoys.
- Missing schema `.refine()` for paired fields.
- Lowest test count (3 files); native-artifact PUT not unit-tested in isolation.
