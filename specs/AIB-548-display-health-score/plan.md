# Implementation Plan: Display health score heart indicator on project cards

**Branch**: `AIB-548-display-health-score` | **Date**: 2026-04-07 | **Spec**: `/home/runner/work/ai-board/ai-board/target/specs/AIB-548-display-health-score/spec.md`
**Input**: Feature specification from `/home/runner/work/ai-board/ai-board/target/specs/AIB-548-display-health-score/spec.md`

## Summary

Add a read-only heart-shaped project health indicator to each project card on the Projects page. The implementation extends the existing project list projection so the initial page data includes the active-module sub-scores from `HealthScore`, a batched server-side Quality Gate summary derived with the existing aggregation logic, and a recomputed global score for each card. The UI then renders a compact, accessible popover without changing existing navigation or adding per-card requests.

Resolved points:

## Phase 1: Design & Contracts

### Data Design

- Extend the projects list projection with a nested `healthSummary` object:
  - `globalScore: number | null`
  - `label: "Excellent" | "Good" | "Fair" | "Poor" | "No data yet"`
  - `color: { text: string; bg: string; fill: string }`
  - `subScores: { security, compliance, tests, specSync, qualityGate, reviewQuality }`
- Active-module sub-scores come from the existing `HealthScore` relation; `qualityGate` is derived through a batched extension of `/home/runner/work/ai-board/ai-board/target/lib/health/quality-gate.ts`.
- `globalScore` is recomputed from the projected sub-scores so the card matches current health-dashboard semantics.
- The no-data case keeps `globalScore` and every missing sub-score nullable.

### UI Design

- Add `/home/runner/work/ai-board/ai-board/target/components/projects/project-health-indicator.tsx` to own:
  - heart icon rendering
  - score/no-data display
  - accessible label text
  - score-band classes and subtle glow treatment
  - read-only popover content with six sub-score rows
- Update `/home/runner/work/ai-board/ai-board/target/components/projects/project-card.tsx` to place the indicator in the upper-right header area near the existing `ProjectMenu`, with propagation guards so the card remains navigable and the indicator itself does not act as a navigation control.

### Contract Design

- Extend `GET /api/projects` and the server page mapping with the `healthSummary` projection.
- Keep the response backward-compatible by adding a new optional-to-new-clients field rather than changing existing field meanings.
- Do not expose scan status, issue counts, or drawer-level details in the projects list response.

### Testing Strategy

- Extend `/home/runner/work/ai-board/ai-board/target/tests/integration/projects/crud.test.ts` to verify `GET /api/projects` includes `healthSummary`, correct numeric values, and explicit null/no-data behavior.
- Create `/home/runner/work/ai-board/ai-board/target/tests/unit/components/projects/project-card.test.tsx` to verify:
  - the numeric heart state renders for scored projects
  - the muted `—` state renders for projects with no health data
  - the popover discloses all six sub-scores with `—` for null values
  - clicking the indicator or popover trigger does not navigate the card
- Reuse the existing health integration coverage in `/home/runner/work/ai-board/ai-board/target/tests/integration/health/health-score.test.ts` as semantic reference rather than duplicating endpoint behavior.
