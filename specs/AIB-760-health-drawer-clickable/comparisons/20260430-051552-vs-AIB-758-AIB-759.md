## Implementation Choices Analysis

### [Spec] FR-005: "Back to latest" hidden when on latest scan
| Ticket | Approach |
|--------|----------|
| AIB-760 | Conditionally renders button only when `selectedScanId !== null && !== latestScanId` |
| AIB-758 | Conditionally renders inline banner with "Latest" button only when `isViewingHistorical` |
| AIB-759 | Always renders "Latest" button, disabled when no selection |

**Best**: AIB-760 / AIB-758 — spec says "MUST NOT be displayed".

### [Spec] FR-012: Empty-report message for historical scan
| Ticket | Approach |
|--------|----------|
| AIB-760 | Dedicated branch shows "Report not available for this scan" when historical + no report |
| AIB-758 | No special message — falls back to generic "predates structured reporting" |
| AIB-759 | Conditional message depending on whether viewing latest vs. historical |

**Best**: AIB-759 / AIB-760 — both meet FR-012.

### Decision Point 1: API shape for fetching one scan
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-760 | Adds `?scanId=` query param to existing list endpoint, returns array of length 1 | Acceptable | Awkward shape (single item wrapped in `scans[]`) |
| AIB-758 | Adds `?scanId=` to list endpoint, modifies `where` clause | Acceptable | Less awkward but mixes list+detail concerns |
| AIB-759 | New REST endpoint `/scans/[scanId]/route.ts` returning `{ scan }` | Aligns better | Cleanest separation; proper 404 on missing |

**Best**: AIB-759 — proper REST resource, returns 404 for missing scan instead of empty array.

### Decision Point 2: Friction-level threshold helper
| Ticket | Approach |
|--------|----------|
| AIB-760 | Inline `getIssueCountLevel` inside drawer-history.tsx |
| AIB-758 | Inline `issuesToLevel` inside drawer-history.tsx |
| AIB-759 | Extracted to `lib/health/issue-friction.ts` with own unit tests |

**Best**: AIB-759 — extracted, tested, reusable across modules.

### Decision Point 3: Reset selection on module switch
| Ticket | Approach |
|--------|----------|
| AIB-760 | **No reset** — selection persists across module switches (latent bug) |
| AIB-758 | Derived state (compare prev prop, reset during render) |
| AIB-759 | Derived state (same React-recommended pattern, with explanatory comment) |

**Best**: AIB-758 / AIB-759 — AIB-760 keeps stale selection across modules.

### Decision Point 4: Interactive row element
| Ticket | Approach |
|--------|----------|
| AIB-760 | `<div role="button" tabIndex={0}>` + custom `onKeyDown` |
| AIB-758 | Native `<button type="button">` |
| AIB-759 | Native `<button type="button">` |

**Best**: AIB-758 / AIB-759 — native semantics, no custom keyboard handler needed.

### Decision Point 5: Issue count badge composition
| Ticket | Approach |
|--------|----------|
| AIB-760 | Removes `AlertTriangle` icon and `Tooltip` wrapper entirely; bare badge with number |
| AIB-758 | Keeps icon inside `Badge`, preserves tooltip |
| AIB-759 | Keeps icon inside `Badge`, removes tooltip (less verbose) |

**Best**: AIB-758 / AIB-759 — icon retains semantic meaning + tooltip clarity.

### Decision Point 6: Query strategy for selected scan
| Ticket | Approach |
|--------|----------|
| AIB-760 | Calls `useScanReport` twice (latest + selected) — both hit list endpoint |
| AIB-758 | Single `useScanReport` hook handles both via optional `scanId` param |
| AIB-759 | Two distinct hooks: `useScanReport` for latest, `useScanById` for detail |

**Best**: AIB-759 — clearest separation; latest scan still uses original cached query, detail has dedicated query key.

## Ranking & Recommendation

### 1. **AIB-759** — Best implementation (score: 87%)
**Why it wins**:
- Dedicated REST endpoint `/scans/[scanId]/route.ts` (cleanest API shape, proper 404)
- `frictionLevelForIssueCount` extracted to `lib/health/issue-friction.ts` with its own unit tests
- Two distinct hooks separate "latest" and "detail" concerns
- Highest test coverage (4 test files including integration + helper unit test)
- Native `<button>` semantics; module switch reset using derived-state pattern with explanatory comment

### 2. **AIB-758** — (score: 78%)
**Why it lost**:
- Misses FR-012 (no special "report not available for this scan" message for historical)
- Couples list + detail concerns on same endpoint
- Friction helper not extracted — inlined

### 3. **AIB-760 (source)** — (score: 74%)
**Why it lost**:
- No reset of `selectedScanId` when user switches between module drawers (latent stale-state bug)
- Uses `<div role="button">` + custom keyboard handler instead of native `<button>`
- Removes `AlertTriangle` icon and tooltip from issue badge — diverges from existing visual pattern
- Two `useScanReport` calls instead of one — slightly wasteful
- Awkward API: returns `{ scans: [single] }` for single-item lookup
- Unit tests only (no integration test for new query path)

## Spec Fulfillment Note

AIB-759 is best on architecture but technically violates FR-005 (button is *disabled* on latest, not *hidden*). AIB-760 perfectly fulfills the spec but has weaker architecture and a state-reset bug. AIB-758 is a balanced middle but misses FR-012.

The FR-005 deviation in AIB-759 is a one-line fix (`hidden={selectedScanId === null}` instead of `disabled`). The state-reset bug in AIB-760 is a more substantive correctness issue.
