# Code Implementation Comparison

## Executive Summary
- **Tickets Evaluated**: AIB-852 (source), AIB-856
- **Best Implementation**: **AIB-852** with **92%**
- **Key Differentiator**: AIB-852 counts transcript-pending sessions toward `expected` and persists an explicit gap-reason enum (`InsightsCoverageGapReason.TRANSCRIPT_NOT_AVAILABLE`), fully satisfying FR-010/FR-011/FR-012. - **Recommendation**: Ship **AIB-852**; close AIB-856 (graft its marker-poisoning re-validation defense if cheap).

## Implementation Choices Analysis

### [Spec] FR-010/011 — "Expected" semantics for transcript-pending sessions
| Ticket | Approach |
|--------|----------|
| AIB-852 | Base query requires only a `JobLog` row; derives `analyzable = captureStatus==='CAPTURED' && rawArtifactKey!=null`. `expected` = all uncovered terminal Claude sessions (incl. pending); `analyzed` = analyzable subset. Pending sessions surface as expected-but-not-analyzed (predicate.ts `countExpectedClaudeSessions`). |
| AIB-856 | Eligibility predicate requires `log.rawArtifactKey != null` at the DB layer. A session without a captured transcript is *not eligible*, so it is excluded from `expected` entirely; the gap only captures transcripts pruned **between** enumeration and download (404). |

**Best**: AIB-852 — matches the spec's "Transcript arrives late → counted as expected-but-not-analyzed" edge case.

### [Spec] FR-012 — Gap reason category
| Ticket | Approach |
|--------|----------|
| AIB-852 | Persists `InsightsCoverageGapReason` enum (`TRANSCRIPT_NOT_AVAILABLE`) on `InsightsReport`; set when `analyzed < expected`. Extensible. |
| AIB-856 | No enum; UI computes `gap = expected - analyzed` and renders a generic "N session(s) unavailable" badge. Reason is implicit. |

**Best**: AIB-852 — explicit, queryable reason category as FR-012 requires.

### Decision Point: Marker-poisoning / caller-list validation
| Ticket | Approach | Constitution |
|--------|----------|--------------|
| AIB-852 | Writes coverage from reported `analyzedJobIds` via `createMany(skipDuplicates)` inside the COMPLETED txn. | OK |
| AIB-856 | Re-validates the caller's `analyzedJobIds` against current eligibility (`filterEligibleClaudeSessionIds`) before writing markers (P-4 defense). | OK+ |

**Best**: AIB-856 — slightly stronger integrity defense against a misbehaving workflow caller.

### 1. **AIB-852** — Best code (score: 92%)
**Why it wins**:
- Fully satisfies FR-010/FR-011/FR-012: pending transcripts counted as expected, gap flagged with a persisted reason enum.

- Coverage gap lacks an explicit reason category (FR-012 partial).
- Fewer test files. Upside: cleaner eligibility model and a marker-poisoning re-validation defense worth grafting.
