**Why AIB-735 fails FR-005**: thresholds set to 60K (warning) / 90K (danger) instead of the spec-prescribed 50K / 100K (`lib/context-metrics.ts:1-2`).

**Why AIB-735 fails FR-009 quality buckets**: uses `Unscored / 0-49 / 50-69 / 70-84 / 85-100` instead of the spec's `Excellent 90-100 / Good 70-89 / Fair 50-69 / Poor 30-49 / Critical 0-29` (`lib/context-metrics.ts:53-65`).

**Why AIB-735 is partial on FR-001/002**: peak is computed from `inputTokens + cacheReadTokens + cacheCreationTokens` (effective context), while the spec literally says "maximum **input tokens** in any single turn". Semantically arguably better, but diverges from the prescribed metric without an ADR.

**Why both are partial on FR-009 filtering**: AIB-736 ships only a static distribution chart (no filter UI). AIB-735 adds a Command/Workflow/Quality grouping selector but no per-criterion filter — both miss the full filter-by-bucket interactivity FR-009 implies.

## Implementation Choices Analysis

### [Spec] Threshold values (FR-005)
| Ticket | Approach |
|--------|----------|
| AIB-736 | 50K / 100K, exactly as spec prescribes (`lib/analytics/aggregations.ts:137-141`) |
| AIB-735 | 60K / 90K — undocumented deviation (`lib/context-metrics.ts:1-2`) |

**Best**: AIB-736.

### [Spec] Quality-score bucket boundaries (FR-009)
| Ticket | Approach |
|--------|----------|
| AIB-736 | Excellent/Good/Fair/Poor/Critical at 90/70/50/30 — matches spec (`lib/analytics/aggregations.ts:158-164`) |
| AIB-735 | Numeric ranges + "Unscored" with different boundaries (50/70/85) |

**Best**: AIB-736.

### [Spec] Peak metric definition (FR-001)
| Ticket | Approach |
|--------|----------|
| AIB-736 | Tracks raw `input_tokens` per turn (matches spec literal) |
| AIB-735 | Tracks `input + cache_read + cache_creation` (effective context window size) |

**Best**: AIB-736 on letter-of-spec; AIB-735's definition is arguably more meaningful for "context rot" analysis but undocumented.

### Decision Point: Analytics filter UX (FR-009)
| Ticket | Approach |
|--------|----------|
| AIB-736 | Single static `ContextHealthChart` (distribution only); gated behind `subscription?.limits.advancedAnalytics` |
| AIB-735 | `PeakContextHistogramChart` + `ContextSizeBreakdownChart` with Command / Workflow / Quality grouping selector; no plan gate |

**Best**: AIB-735 on UX richness — but missing the plan gate is also a deviation from the analytics-tier pattern used for `qualityScore` charts.

### Decision Point: Subscription gating
| Ticket | Approach |
|--------|----------|
| AIB-736 | Behind `advancedAnalytics` (consistent with QualityScoreTrendChart, DimensionComparisonChart) |
| AIB-735 | Always shown to all plans |

**Best**: AIB-736 — follows existing analytics-tier convention.

### Decision Point: Telemetry merge logic
| Ticket | Approach |
|--------|----------|
| AIB-736 | Computes peak/avg/turn-count merge inline in `updateJobMetrics`; covered by 3 dedicated integration tests (multi-turn, single-turn, multi-batch merge) |
| AIB-735 | Same merge approach but no multi-batch merge test in `tests/integration/telemetry/agent-agnostic.test.ts` |

**Best**: AIB-736 — stronger telemetry test coverage for batch-merge edge case.

### Decision Point: Code organization
| Ticket | Approach |
|--------|----------|
| AIB-736 | Helpers added to existing `lib/analytics/aggregations.ts` |
| AIB-735 | New module `lib/context-metrics.ts` + light refactor of `jobs-timeline.tsx` (extracts `hasTelemetryMetrics`, `getContextBadgeClassName`, removes filler comments) |

**Best**: AIB-735 — cleaner module boundary, drive-by simplification of `jobs-timeline.tsx`.
