## Implementation Choices Analysis

### [Spec] Storage key shape (FR-005)
| Ticket | Approach |
|--------|----------|
| AIB-783 | `raw-logs/{p}/{t}/{j}.jsonl.gz` — distinct top-level prefix |
| AIB-776 | `logs/{p}/{t}/{j}.native.jsonl.gz` — suffix in shared prefix |
| AIB-780 | `logs/{p}/{t}/{j}-raw.jsonl.gz` — suffix in shared prefix |
| AIB-781 | `logs/{p}/{t}/{j}.native.jsonl.gz` — suffix in shared prefix |

**Best**: AIB-783 — distinct prefix simplifies bucket-level retention sweeps and cleanly separates the two artifact classes for ops auditing.

### [Spec] Retrieval API shape (FR-006)
| Ticket | Approach |
|--------|----------|
| AIB-783 | New sibling `GET /…/logs/raw-native` |
| AIB-776 | New sibling `GET /…/logs/raw-native` |
| AIB-780 | Reuses `GET /…/logs/raw?type=native` query parameter |
| AIB-781 | New sibling `GET /…/logs/native` (different name) |

**Best**: AIB-783/776 — the spec's auto-resolved decision **explicitly rejects** a query-parameter approach ("complicates caching and authorization audits"). AIB-780 violates this design constraint.

### [Spec] Non-Claude gate at PUT (FR-008)
| Ticket | Approach |
|--------|----------|
| AIB-783 | Selects `ticket.agent`, returns 409 `AGENT_NOT_CLAUDE` |
| AIB-776 | Resolves effective agent (`ticket.agent ?? project.defaultAgent`), returns 422 `AGENT_NOT_SUPPORTED` |
| AIB-780 | No agent gate in PUT route — accepts upload for any job |
| AIB-781 | No agent gate in PUT route — accepts upload for any job |

**Best**: AIB-776 (most defensible — handles ticket-level override and project default). AIB-783 also met. AIB-780/781 rely solely on the runner-side gate, weakening the FR-008 guarantee against a misbehaving runner.

### Decision Point: Schema validation
| Ticket | Approach | Notes |
|--------|----------|-------|
| AIB-783 | Cross-field zod `.refine()` enforcing key+size pairing tied to `CAPTURED` | Strongest |
| AIB-776 | Schema field added, no cross-field refine | OK |
| AIB-780 | Schema field added, no cross-field refine | OK |
| AIB-781 | Schema field added, no cross-field refine | OK |

**Best**: AIB-783 — prevents partial-state submissions at the API boundary.

### Decision Point: Pruning extension (FR-011)
| Ticket | Approach |
|--------|----------|
| AIB-783 | Extracted `tryDeleteArtifact(key, label)` helper, applies to both keys |
| AIB-776 | Inline second delete call per row |
| AIB-780 | Loop over `[artifactKey, rawArtifactKey]` array |
| AIB-781 | Inline second delete call per row |

**Best**: AIB-783 — cleanest refactor; helper labels each delete for log-grep separation.

## Ranking & Recommendation

### 1. **AIB-783** (source) — 91%
**Why it wins**:
- Only implementation with a distinct `raw-logs/` storage prefix (cleanest FR-005)
- Sibling `/raw-native` endpoint fully matches spec; CLAUDE.md updated to reflect it
- Hard non-Claude gate at PUT (409) + GET (404)
- Cross-field zod refinement; helper-based prune refactor

### 2. **AIB-776** — 84%
**Why it lost**:
- Storage key uses suffix in shared prefix, less ops-friendly than dedicated prefix
- Otherwise the closest competitor — strongest non-Claude gate (uses effective agent)

### 3. **AIB-781** — 70%
**Why it lost**:
- No non-Claude gate at PUT — relies entirely on runner-side check
- Endpoint named `/native` instead of mirroring the existing `/raw` name
- Lowest test coverage (3 files)
- Field naming (`nativeArtifactKey`) diverges from spec convention

### 4. **AIB-780** — 64%
**Why it lost**:
- Uses `?type=native` query parameter on `/logs/raw` — **explicitly rejected** by the spec's auto-resolved decision on Retrieval API surface
- No non-Claude gate at PUT route
- Strong test coverage cannot offset a violation of an explicit design decision
