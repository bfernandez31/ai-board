## Implementation Choices Analysis

### [Spec] FR-014 — Avoid disproportionate DB growth
| Ticket | Approach |
|--------|----------|
| AIB-720 | Stores gzipped event JSON as `JobExecutionLog.artifactBytes` (Bytes) directly in Postgres. |
| AIB-715 | Stores gzipped JSONL in Vercel Blob; DB row keeps only metadata + 320-char preview. |

**Best**: AIB-715 — FR-014 explicitly targets the transactional-DB growth risk that AIB-720 introduces.

### [Spec] FR-002 — Multi-agent log capture
| Ticket | Approach |
|--------|----------|
| AIB-720 | Generic `normalizeProviderLog` in `lib/job-logs/normalize.ts`; relies on `run-agent.sh` producing a pre-structured JSON bundle per agent. |
| AIB-715 | Dedicated `.github/scripts/lib/normalize-{claude,codex,gemini,mistral}.mjs` modules + shared base. |

**Best**: AIB-715 — per-agent parsers preserve format-specific semantics end-to-end.

### [Spec] FR-013 — 30-day retention + pruning
| Ticket | Approach |
|--------|----------|
| AIB-720 | `pruneExpiredJobExecutionLogs()` function exists, but no scheduler/workflow triggers it. |
| AIB-715 | `/api/maintenance/prune-logs` endpoint + `.github/workflows/nightly-log-prune.yml` cron (01:15 UTC). |

**Best**: AIB-715 — AIB-720's code would require additional ops wiring to actually prune.

### Decision Point: PII redaction
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-720 | Inline regex in normalize.ts (server-side only) | Yes | Simpler, but raw unredacted events travel over the wire before server redaction. |
| AIB-715 | `redactor.mjs` runner-side + `app/lib/logs/redactor.ts` server-side | Yes | Defense in depth; secrets redacted before leaving runner. |

**Best**: AIB-715 — runner-side redaction is the stronger Security-First posture.

### Decision Point: Test coverage breadth
| Ticket | Unit | Integration | E2E |
|--------|-----:|------------:|----:|
| AIB-720 | 2 (normalizer, detail modal) | 5 | 0 |
| AIB-715 | 5 (normalizer, preview, redactor, viewer, stats) | 5 | 1 (Playwright) |

**Best**: AIB-715 — broader pyramid including a Playwright E2E over the log viewer.

## Ranking & Recommendation

### 1. **AIB-715** — Best code (score: 93%)
**Why it wins**:
- Satisfies FR-014 by design (external blob storage, metadata-only row).
- Ships a production-ready retention pipeline (cron + endpoint), not just a helper function.
- Per-agent normalizers address FR-002 with format-specific fidelity.
- Dual-layer PII redaction (runner + server) is more defensible.
- Broader test pyramid including a Playwright E2E.

### 2. **AIB-720 (source)** — (score: 81%)
**Why it lost**:
- Gzipped artifact bytes in a Postgres `Bytes` column directly contradicts FR-014.
- Pruning code exists but no scheduler/workflow invokes it (FR-013 partial).
- Single generic normalizer weakens FR-002 fidelity across four distinct agent output formats.
- No E2E coverage of the log viewer surface.
