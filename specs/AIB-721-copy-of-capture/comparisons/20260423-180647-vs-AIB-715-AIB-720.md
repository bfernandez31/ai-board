## Implementation Choices Analysis

### [Spec] FR-006 — Full transcript outside primary DB
| Ticket | Approach |
|---|---|
| AIB-721 | `JobLog.rawContent TEXT` + `entries TEXT` in Postgres (5 MB cap). |
| AIB-715 | `@vercel/blob` (`app/lib/blob/client.ts`) referenced by `JobLog.artifactKey`; gzipped NDJSON, 25 MB cap. |
| AIB-720 | `JobExecutionLog.artifactBytes BYTEA` (gzipped) — durable but in-row. |

**Best**: AIB-715 — only branch with a true external blob store as the spec requires.

### [Spec] FR-007 — Secret redaction
| Ticket | Approach |
|---|---|
| AIB-721 | No redactor module present; secrets traverse storage. |
| AIB-715 | Paired `.github/scripts/lib/redactor.mjs` + `app/lib/logs/redactor.ts` with kinded `[REDACTED:<kind>]` placeholder; runs on the runner before bytes leave. |
| AIB-720 | Server-side only via `lib/job-logs/normalize.ts`; plain `[REDACTED]`; secrets reach the API in the clear. |

**Best**: AIB-715 — defense-in-depth with runner-side redaction matches the spec verbatim.

### [Spec] FR-001 — Per-agent capture
| Ticket | Approach |
|---|---|
| AIB-721 | Single `upload-agent-logs.sh`; all agent dispatch via runtime regex in `lib/logs/log-parser.ts`. |
| AIB-715 | Four dedicated normalizers `normalize-{claude,codex,mistral,gemini}.mjs` extending `normalize-base.mjs`. |
| AIB-720 | Generic `jq` line splitter in `run-agent.sh::write_job_log_bundle`; no per-agent awareness. |

**Best**: AIB-715 — explicit per-agent path matches FR-001 + FR-002 schema versioning.

### [Spec] FR-011 / FR-024 — Raw download + per-entry copy
| Ticket | Approach |
|---|---|
| AIB-721 | Neither endpoint nor copy button. |
| AIB-715 | `GET .../logs/raw?format=jsonl` streams gzipped artifact; `log-event-row.tsx` exposes per-entry Copy. |
| AIB-720 | Neither. |

**Best**: AIB-715 — only branch fulfilling both requirements.

### Decision Point: UNAVAILABLE fallback
| Ticket | Approach |
|---|---|
| AIB-721 | Relies on absence; `LogStatus.NONE` enum with no UNAVAILABLE state. |
| AIB-715 | `CaptureStatus.UNAVAILABLE` written by API when summary submission marks failure. |
| AIB-720 | Active fallback: `PATCH /api/jobs/[id]/status` upserts an UNAVAILABLE log when terminal status arrives without a bundle. |

**Best**: AIB-720 — strongest active enforcement of FR-017 (the one place 720 outshines 715, though 715 also satisfies FR-017 via the upload path).

### Decision Point: Pruning trigger
| Ticket | Approach |
|---|---|
| AIB-721 | `POST /api/cron/prune-logs` route, `CRON_SECRET` auth — no workflow file added to schedule it. |
| AIB-715 | Dedicated `.github/workflows/nightly-log-prune.yml` cron (01:15 UTC) calling `/api/maintenance/prune-logs`. |
| AIB-720 | `pruneExpiredJobExecutionLogs` function exists; no HTTP endpoint or workflow in diff. |

**Best**: AIB-715 — only branch that wires the schedule end-to-end.

## Ranking & Recommendation

### 1. **AIB-715** — Best implementation (score: 95%)
**Why it wins**:
- Only branch that satisfies FR-006 (external blob), FR-011 (raw download), FR-024 (per-entry copy), and FR-026 (schema versioning).
- Defense-in-depth redaction on the runner with kinded placeholders.
- Per-agent normalizer modules instead of brittle regex branching.
- Only branch with an end-to-end e2e test and a wired-up nightly prune workflow.

### 2. **AIB-720** — (score: 72%)
**Why it lost**:
- Stores transcript bytes in Postgres `BYTEA` — fails FR-006.
- No raw-download endpoint, no per-entry copy, no schema version.
- Generic line-splitter loses per-agent richness (`run-agent.sh::write_job_log_bundle`).
- Strong UNAVAILABLE fallback in `PATCH /jobs/:id/status` is the one architectural standout.

### 3. **AIB-721** — Source (score: 67%)
**Why it lost**:
- No secret redaction in the diff at all — material security regression vs spec.
- Stores both `rawContent` and serialized entries as TEXT in Postgres (fails FR-006).
- No raw-download, no copy button, no UNAVAILABLE state, no scheduled prune.
- Cleanest TypeScript and decent test count, but spec coverage is the worst of the three.
