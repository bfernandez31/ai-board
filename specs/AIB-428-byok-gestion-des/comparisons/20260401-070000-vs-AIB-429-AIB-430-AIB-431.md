## Implementation Choices Analysis

### [Spec] Workflow credential retrieval with env var mapping
| Ticket | Approach |
|--------|----------|
| AIB-428 | Internal endpoint `/api/internal/credentials` with `buildWorkflowPayload()` returning `{envVar, secret, credentialType}`. Inline credential fetch in 2 workflow YAML files. |
| AIB-429 | `POST /api/workflows/credentials` with `{projectId, provider}` body. Returns `{credentialType, apiKey}` but no env var name mapping. No workflow YAML integration. |
| AIB-430 | `GET /api/projects/:id/ai-credentials/owner` + reusable `load-ai-credential.sh` script. All 6 workflow files updated. Env var mapping via `AI_CREDENTIAL_ENV_VAR_MAP`. |
| AIB-431 | `POST /api/internal/workflows/projects/:id/providers/:provider/credential` with eligibility pre-check. RESTful URL structure. Job route blocking. |

**Best**: AIB-430 — Most production-ready workflow integration with reusable shell script and all 6 workflows updated. AIB-428 and AIB-431 also strong but cover fewer workflow files.

### [Spec] Pre-dispatch credential check (FR-012)
| Ticket | Approach |
|--------|----------|
| AIB-428 | `dispatchAIBoardWorkflow` calls `getOwnerCredential()` before dispatch — blocks in the dispatch function itself. |
| AIB-429 | No pre-dispatch check implemented. |
| AIB-430 | `lib/workflows/transition.ts` checks credential before stage transition — blocks at the board level. |
| AIB-431 | `app/api/projects/[projectId]/jobs/route.ts` checks `getProjectOwnerCredentialEligibility()` before job creation — blocks at the API layer. Also adds `StageTransitionError` for structured error propagation. |

**Best**: AIB-431 — Blocks at the API layer with structured error codes and a custom `StageTransitionError` class that propagates error details to the UI. Most robust error handling pattern.

### [Spec] Test button for credential re-validation (US3.1)
| Ticket | Approach |
|--------|----------|
| AIB-428 | Dedicated `POST /api/credentials/:id/test` endpoint + `CredentialTestButton` component. Updates readinessStatus/verificationCode/verificationMessage. |
| AIB-429 | No test button. Has `POST /api/credentials/validate` but only for pre-save validation. |
| AIB-430 | Has `POST /api/user/ai-credentials/validate` for pre-save only. No post-save test. |
| AIB-431 | No dedicated test endpoint or button. Validation happens only during save. |

**Best**: AIB-428 — Only implementation that fulfills the explicit test button acceptance criterion.
