## Implementation Choices Analysis

### [Spec] Unknown field handling strategy
| Ticket | Approach |
|--------|----------|
| AIB-486 | `.strict()` on all sub-schemas + root — rejects unknown fields with descriptive errors via `unrecognized_keys` Zod code |
| AIB-493 | `.strip()` on root only — silently removes unknown fields, sub-schemas unchanged |

**Best**: AIB-486 — Spec explicitly requires rejection with errors (FR-003, FR-005). `.strip()` silently removes, which contradicts the spec requirement for "descriptive validation errors."

### [Spec] Service credential stripping
| Ticket | Approach |
|--------|----------|
| AIB-486 | Dedicated exported `stripServiceCredentials()` function in validations/config.ts, called from config-sync.ts |
| AIB-493 | Inline destructuring in config-sync.ts (`({ username: _u, password: _p, ...rest }) => rest`) |

**Best**: AIB-486 — Reusable exported function enables direct testing and reuse from any consumer. AIB-493's inline approach works but is not independently testable.

### Decision Point 1: Dead code removal
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-486 | Removes entire `collectUnknownFieldWarnings` + `KNOWN_*_KEYS` (69 lines) since `.strict()` handles it natively | Yes — clean code | Smaller surface area |
| AIB-493 | Retains `collectUnknownFieldWarnings` + all known-key sets (now dead code since `.strip()` bypasses them) | No — dead code | Misleading: function exists but `.strip()` makes it decorative |

**Best**: AIB-486 — Dead code removal is correct since `.strict()` natively handles unknown field detection.

### Decision Point 2: Sub-schema strictness
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-486 | `.strict()` on ProjectSectionSchema, RuntimeSectionSchema, CommandsSectionSchema, ServiceConfigSchema, AgentSectionSchema | Yes — Principle IV: validate ALL inputs | Complete validation at every level |
| AIB-493 | No changes to sub-schemas | Partial | Only root-level unknowns handled |

**Best**: AIB-486 — Constitution Principle IV requires validating ALL user inputs. Sub-schema strictness catches `project.typo`, `runtime.extra`, etc.

### Decision Point 3: Error mapping for unknown fields
| Ticket | Approach |
|--------|----------|
| AIB-486 | Extends `mapZodErrors` with `unrecognized_keys` handler, using `.flatMap()` to expand multi-key errors into individual `ValidationError` entries with `type: 'unknown_field'` |
| AIB-493 | No error mapping changes (`.strip()` produces no errors) |

**Best**: AIB-486 — Provides clear, per-field error messages matching FR-005 requirements.
