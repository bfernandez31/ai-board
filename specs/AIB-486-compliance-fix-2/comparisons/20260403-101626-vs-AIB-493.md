## Implementation Choices Analysis

### [Spec] Service Credential Stripping
| Ticket | Approach |
|--------|----------|
| AIB-486 | Dedicated `stripServiceCredentials()` function exported from validations/config.ts, reusable across sync and API layers |
| AIB-493 | Inline destructuring in config-sync.ts only — not reusable for API responses |

**Best**: AIB-486 — Reusable function ensures credentials are stripped consistently at every call site, not just sync.

### [Spec] Unknown Field Handling
| Ticket | Approach |
|--------|----------|
| AIB-486 | `.strict()` on ALL schema sections (root + project + runtime + commands + agent) with `unrecognized_keys` error mapping in `mapZodErrors` |
| AIB-493 | `.strip()` on root schema only — silently removes unknown fields instead of rejecting them |

**Best**: AIB-486 — The spec explicitly requires *rejecting* unknown fields with validation errors. `.strip()` silently passes, violating the requirement and the constitution's "validate ALL user inputs" rule.

### Decision Point: Schema Validation Strategy
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-486 | `.strict()` + error reporting | Yes (IV: validate ALL inputs) | Stricter — users get clear errors |
| AIB-493 | `.strip()` (silent removal) | No (silent pass violates IV) | Lenient — masks invalid input |

**Best**: AIB-486 — `.strict()` enforces constitution principle IV, gives users actionable feedback.

### Decision Point: Test Coverage Approach
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-486 | 5 unit tests for `stripServiceCredentials` + 1 integration test for full sync pipeline with credentials | Yes (III) | Comprehensive edge cases (partial credentials, no services) |
| AIB-493 | 1 unit test verifying credentials pass schema + 1 test verifying strip behavior + unrelated billing test refactor | Partial (III) | Covers happy path only, billing test unrelated to feature |

**Best**: AIB-486 — Tests cover edge cases (partial credentials, no services, no credentials) plus full integration pipeline.
