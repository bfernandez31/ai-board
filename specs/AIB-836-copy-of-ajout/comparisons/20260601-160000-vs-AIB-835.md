## Implementation Choices Analysis

### [Spec] Add Claude Opus 4.8 to Claude model registry
| Ticket | Approach |
|--------|----------|
| AIB-836 | Adds `claude-opus-4-8` at top of `CLAUDE_MODEL_IDS`, plus matching label, pricing entry, context window entry. |
| AIB-835 | Same additions; identical registry shape. |

**Best**: Tie — both implement the registry addition correctly.

### [Spec] Use Opus 4.8 as the new Opus default
| Ticket | Approach |
|--------|----------|
| AIB-836 | Sets `CLAUDE_GLOBAL_FALLBACK_MODEL = 'claude-opus-4-8'`; in `SMART_DEFAULTS`, hardcodes the literal `'claude-opus-4-8'` for `specifyModel`/`planModel`. |
| AIB-835 | Sets `CLAUDE_GLOBAL_FALLBACK_MODEL = 'claude-opus-4-8'`; in `SMART_DEFAULTS`, references `CLAUDE_GLOBAL_FALLBACK_MODEL` (DRY — one source of truth for the Opus default). |

**Best**: AIB-835 — using the fallback constant in `SMART_DEFAULTS` avoids a future drift if the global fallback changes again.

### [Spec] Workflow `ANTHROPIC_MODEL` fallbacks updated
| Ticket | Approach |
|--------|----------|
| AIB-836 | Updates all nine workflow files (`ai-board-assist`, `health-scan`, `inbox-analysis`, `iterate`, `onboard`, `quick-impl`, `retro-spec`, `speckit`, `verify`) + `.ai-board/config.yml`. **Additionally** changes `verify.yml`'s expression to `(inputs.agent == 'CLAUDE' && inputs.model != '') && inputs.model || 'claude-opus-4-8'` so non-Claude tickets (Codex/Mistral/Gemini) never leak a non-Claude model id into the Claude CLI for the code-review step. |
| AIB-835 | Updates the same workflow files and `.ai-board/config.yml`, but keeps the existing `inputs.model != '' && inputs.model || ...` expression in `verify.yml` unchanged — i.e. still vulnerable to the leak. |

**Best**: AIB-836 — also fixes a real predating bug (the same one called out in the most recent merged commit `1c476f3b fix(verify): pin code-review to a Claude model on non-Claude tickets`). Per CLAUDE.md, fixing predating issues found during the change is expected.

## Ranking & Recommendation

### 1. **AIB-836** — Best implementation (score: 84%)
**Why it wins**:
- Fully meets all spec acceptance criteria.
- Ships an additional `verify.yml` correctness fix that prevents the Claude CLI from receiving non-Claude model ids on Codex/Mistral/Gemini tickets — a real predating bug.
- Minimal, focused diff (28+/19−). No prettier-style reformatting noise.
- Touches only what is strictly necessary to deliver the model bump.

**What it gives up**:
- No dedicated unit tests for the registry / smart defaults / workflow-file invariant — relies on one updated integration test.
- `SMART_DEFAULTS` hardcodes `'claude-opus-4-8'` literally instead of referencing `CLAUDE_GLOBAL_FALLBACK_MODEL`.

### 2. **AIB-835** — Strong contender (score: 80%)
**Why it lost**:
- Misses the `verify.yml` non-Claude leak fix that AIB-836 ships. That's a concrete correctness regression risk on Codex tickets.
- Large prettier-style reformatting of `ai-models-card.tsx` (177+/131−) is out-of-scope churn that makes review and rollback noisier.

**What it does better**:
- Three new dedicated test files, including a workflow-file invariant scan — best safety net of the two for future default bumps.
- `SMART_DEFAULTS` references `CLAUDE_GLOBAL_FALLBACK_MODEL` (single source of truth).
- Also updates the Codex fallback label to follow `CODEX_GLOBAL_FALLBACK_MODEL` symmetrically.
