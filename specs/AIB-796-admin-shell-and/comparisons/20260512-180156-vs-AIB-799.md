## Implementation Choices Analysis

### [Spec] FR-001/FR-002 — Admin status delivery & no-leak guarantee
| Ticket | Approach |
|--------|----------|
| AIB-796 | Async `RootLayout` calls `getViewerIsAdmin(request)` per request, prop-drills `isAdmin` through `Header → UserMenu/MobileMenu`. Non-admins receive HTML with literally no admin link rendered (proven by `tests/integration/admin-shell-isolation.test.ts` against `renderToStaticMarkup`). |
| AIB-799 | Adds `isAdmin` to next-auth session via the `session` callback; client components read `session.user.isAdmin` from `useSession()`. SSR pass renders nothing (session loading), then hydrates with admin link only for admins. The session JSON shipped to every client still contains `isAdmin: false` for non-admins. |

**Best**: AIB-796 — Matches the spec literally ("on each render", "MUST NOT contain... any DOM attribute that signals the existence of the admin surface"). AIB-799 ships `isAdmin: false` in the session payload, which is a low-grade fingerprint that an admin surface exists, and there is no test pinning the SSR no-leak invariant.

### [Spec] FR-012 — Sidebar extensibility (items + divider)
| Ticket | Approach |
|--------|----------|
| AIB-796 | `ADMIN_SIDEBAR_ITEMS: ReadonlyArray<AdminSidebarItem \| AdminSidebarDivider>` — divider is a first-class entry kind; `AdminShell` renders `<hr>` automatically. |
| AIB-799 | `ADMIN_NAV_ITEMS: readonly AdminNavItem[]` — no divider primitive; adding a group separator requires editing the sidebar component layout. |

**Best**: AIB-796 — Explicitly satisfies "MUST support inserting a divider between groups of items without code restructuring."

### Decision Point — Active-path matcher placement
| Ticket | Approach | Trade-offs |
|--------|----------|------------|
| AIB-796 | Extracted to `lib/admin/active-path.ts` with its own unit test file. | Reusable, isolated, single-source-of-truth. |
| AIB-799 | Inline `isItemActive` inside `admin-sidebar.tsx`, driven by a per-item `match: 'exact' \| 'prefix'` flag. | Slightly more configurable per item, but couples logic to the component and prevents reuse from server code. |

**Best**: AIB-796 — Matcher is the kind of pure logic the constitution rewards extracting (cheap to unit-test, immune to React-rendering concerns).

### Decision Point — Visual active-state indicator
| Ticket | Approach |
|--------|----------|
| AIB-796 | `border-l-2 border-primary` + `bg-accent/30` directly on the `<Link>`. |
| AIB-799 | Absolute-positioned `<span>` for the lateral bar + `bg-accent/60 text-accent-foreground` on the `<Link>`. |

**Best**: Stylistic tie — AIB-799 looks marginally more polished; AIB-796 is more compact. Not a deciding factor.

## Ranking & Recommendation

### 1. AIB-796 — Best code (score: 92%)
**Why it wins**:
- Server-rendered admin gating with an explicit SSR no-leak integration test — directly answers FR-002's "hidden-but-present markup is not acceptable."
- Sidebar items are an extensible data structure with a first-class divider type, satisfying FR-012.
- Active-state matcher is a pure helper in `lib/admin/active-path.ts` with dedicated unit tests.

### 2. AIB-799 — (score: 85%)
**Why it lost**:
- Relies on `session.user.isAdmin` reaching the client via `useSession()`; the session payload contains `isAdmin: false` for non-admins, a low-grade leak the source's prop-drilled approach avoids entirely.
- No divider primitive in `ADMIN_NAV_ITEMS`, so FR-012's "support inserting a divider… without code restructuring" is unmet.
- No integration test asserting the non-admin SSR pass contains zero admin markup (SC-002).
