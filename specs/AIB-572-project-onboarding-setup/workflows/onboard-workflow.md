# Workflow Specification: onboard.yml

**Feature Branch**: `AIB-572-project-onboarding-setup`
**Date**: 2026-04-08

## Overview

The onboard workflow initializes an external repository for use with AI Board. It runs in two phases: deterministic stack detection (Phase 1) and LLM content generation (Phase 2). All generated files are committed atomically to the target repository's default branch.

## Trigger

```yaml
on:
  workflow_dispatch:
    inputs:
      project_id:
        description: 'Project ID'
        required: true
        type: string
      setup_job_id:
        description: 'Setup job ID for status callbacks'
        required: true
        type: string
      githubRepository:
        description: 'Target repository (owner/repo format)'
        required: true
        type: string
      agent:
        description: 'Agent CLI to use (claude-code or codex)'
        required: true
        type: string
      callback_url:
        description: 'Base URL for status callbacks'
        required: true
        type: string
```

## Environment

```yaml
env:
  GITHUB_TOKEN: ${{ secrets.GH_PAT }}
  WORKFLOW_TOKEN: ${{ secrets.WORKFLOW_TOKEN }}
```

Agent credentials passed via environment variable based on agent input:
- claude-code: `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`
- codex: `OPENAI_API_KEY` or `CODEX_OAUTH_JSON`

## Job: onboard

**runs-on**: ubuntu-latest
**timeout-minutes**: 30
**permissions**: contents: write

### Steps

#### 1. Status Callback: RUNNING

```bash
curl -X PATCH "${{ inputs.callback_url }}/api/jobs/${{ inputs.setup_job_id }}/status" \
  -H "Authorization: Bearer $WORKFLOW_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status": "RUNNING", "workflowRunId": ${{ github.run_id }}}'
```

#### 2. Checkout AI Board (sparse — scripts only)

```yaml
- uses: actions/checkout@v4
  with:
    sparse-checkout: |
      .specify/scripts/bash/
      .claude/commands/
    path: ai-board
```

#### 3. Clone Target Repository

```bash
git clone "https://x-access-token:${GITHUB_TOKEN}@github.com/${{ inputs.githubRepository }}.git" target-repo
cd target-repo
DEFAULT_BRANCH=$(git symbolic-ref refs/remotes/origin/HEAD | sed 's@^refs/remotes/origin/@@')
echo "DEFAULT_BRANCH=$DEFAULT_BRANCH" >> $GITHUB_ENV
```

#### 4. Phase 1 — Deterministic Stack Detection

```bash
cd target-repo
bash ../ai-board/.specify/scripts/bash/detect-stack.sh --output-dir .ai-board
```

**Outputs**:
- `.ai-board/config.yml` — project configuration
- `.ai-board/analysis.json` — detection summary for LLM phase

**Failure mode**: If this step fails, the entire workflow fails (no files committed).

#### 5. Install Agent CLI

Conditional based on `inputs.agent`:
- `claude-code`: `npm install -g @anthropic-ai/claude-code`
- `codex`: `npm install -g @openai/codex`

#### 6. Phase 2 — LLM Content Generation

```bash
cd target-repo

# Skip if CLAUDE.md already exists
if [ ! -f "CLAUDE.md" ]; then
  claude --print -p "$(cat ../ai-board/.claude/commands/onboard.md)" \
    --context "$(cat .ai-board/analysis.json)"
fi
```

**Outputs** (generated by agent):
- `CLAUDE.md` — project-specific development guidelines (skipped if exists)
- `.ai-board/memory/constitution.md` — governance principles
- `AGENTS.md` → symlink to `CLAUDE.md`

**Failure mode**: If this step fails, proceed to commit Phase 1 outputs only (partial success).

#### 7. Update .gitignore

```bash
cd target-repo
if ! grep -q "^\.ai-board/" .gitignore 2>/dev/null; then
  echo "" >> .gitignore
  echo "# AI Board configuration" >> .gitignore
  echo ".ai-board/" >> .gitignore
fi
```

**Note**: `.ai-board/config.yml` is committed but the directory is gitignored for future runtime files. The config.yml commit precedes the gitignore update in the same commit, so it is included. Wait — this contradicts the intent. The `.ai-board/` directory should NOT be gitignored if `config.yml` needs to be tracked. Revisit: only gitignore `.ai-board/memory/` and runtime files, not `config.yml`.

**Correction**: Do NOT gitignore `.ai-board/`. Instead, add specific gitignore entries for runtime-only paths if needed. The `config.yml` must remain tracked in the repository for config sync to work (it fetches from GitHub).

#### 8. Commit and Push

```bash
cd target-repo
git config user.name "ai-board[bot]"
git config user.email "ai-board[bot]@users.noreply.github.com"

git add -A
COMMITTED_FILES=$(git diff --cached --name-only)
git commit -m "chore: initialize AI Board project configuration

Generated by AI Board onboarding workflow.
Files: $(echo "$COMMITTED_FILES" | tr '\n' ', ')"

git push origin "$DEFAULT_BRANCH"

echo "COMMITTED_FILES<<EOF" >> $GITHUB_ENV
echo "$COMMITTED_FILES" >> $GITHUB_ENV
echo "EOF" >> $GITHUB_ENV
```

#### 9. Status Callback: COMPLETED

```bash
# Determine if partial (Phase 2 failed but Phase 1 succeeded)
IS_PARTIAL=${{ steps.phase2.outcome == 'failure' && 'true' || 'false' }}

curl -X PATCH "${{ inputs.callback_url }}/api/jobs/${{ inputs.setup_job_id }}/status" \
  -H "Authorization: Bearer $WORKFLOW_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{
    \"status\": \"COMPLETED\",
    \"isPartial\": $IS_PARTIAL,
    \"completedFiles\": $(echo "$COMMITTED_FILES" | jq -R -s 'split("\n") | map(select(. != ""))')
  }"
```

#### 10. Status Callback: FAILED (on failure)

```yaml
if: failure() && steps.phase1.outcome == 'failure'
```

```bash
curl -X PATCH "${{ inputs.callback_url }}/api/jobs/${{ inputs.setup_job_id }}/status" \
  -H "Authorization: Bearer $WORKFLOW_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status": "FAILED", "errorMessage": "Stack detection failed. Check repository access and permissions."}'
```

## Idempotency

- If `config.yml` already exists, Phase 1 overwrites it (fresh detection)
- If `CLAUDE.md` already exists, Phase 2 skips generation (preserves manual edits)
- If `constitution.md` already exists, Phase 2 skips it
- The workflow is safe to retry from scratch

## Post-Workflow

After the COMPLETED callback:
1. The API handler triggers `syncProjectConfig(project)` to pull the new `config.yml` into the database
2. The setup page detects COMPLETED status via polling and shows success state
3. The user clicks "Go to Project Board" → redirected to `/projects/{id}/board`
