- **Tickets Evaluated**: AIB-893 (source), AIB-890, AIB-891, AIB-892

## Implementation Choices Analysis

### [Spec] Stop when complete / empty batch (FR-006)
| Ticket | Approach |
|---|---|
| AIB-893 | `exhaustedAtTotal` state is set when a batch is short, empty or all duplicates. Loading starts again if `shipTotal` grows |
| AIB-890 | `exhaustedAtTotal` is set when `addedCount === 0` |
| AIB-891 | No exhaustion state. If an empty batch comes back while count < total, the effect fires again and the requests loop |
| AIB-892 | No exhaustion state. The observer is rebuilt whenever `isLoadingMore` changes, which can loop on an empty batch |

**Best**: AIB-893, because it handles short batches as well as empty ones.

### [Spec] Header counter shows `loaded/total` (FR-007, AC 1.3 "120/120")
In AIB-893 the header always shows `n/total`. AIB-890 keeps the `totalCount > ticketCount` condition, so a fully loaded column shows "120". AIB-891 and AIB-892 only pass `totalCount` while more tickets remain.

### [Spec] Polling preservation (FR-010)
| Ticket | Approach |
|---|---|
| AIB-893 | Client-side `mergeLoadedShipTickets` in the query function |
| AIB-890 | Pure `mergeRefreshedTickets` in `lib/tickets/ship-pagination.ts`, unit-tested |
| AIB-891 | Exported `mergeLoadedShipTickets`, unit-tested |
| AIB-892 | Adds a server `shipLimit` param (max 500) and refetches every loaded ticket on each poll. Once more than 500 are loaded, the request fails validation with a 400 and polling breaks. Each poll also returns heavier payloads |

**Best**: AIB-890 and AIB-893. AIB-890's version is the cleanest because it is a pure function with tests.

### [Spec] Drag & drop (FR-011)
AIB-893, AIB-890 and AIB-891 pass `isDragging` as a pause flag. AIB-892 has no drag guard.

### Decision Point 1: Hook architecture
| Ticket | Approach | Trade-offs |
|---|---|---|
| AIB-893 | `useMutation` with a ref guard and `retry: 0`, plus a dedicated `useInfiniteScrollTrigger` hook | Reusable and keeps TanStack idioms. The trigger re-attaches the observer after every commit |
| AIB-890 | Hand-rolled async loader with status, mounted and in-flight refs | Unmount-safe, but drops `useMutation` and adds a lot of refs. Reuses the existing `useIntersectionObserver` through a `useMemo` ref workaround |
| AIB-891 | Inline IntersectionObserver plus a `getBoundingClientRect` re-check | Simple, but the logic lives in the column component |
| AIB-892 | Observer rebuilt whenever loading state changes | Fragile |

**Best**: AIB-893.

## Ranking & Recommendation

### 1. **AIB-893**: Best code (score: 92%)
- Meets every acceptance criterion, including the `120/120` counter and the drag pause
- Exhaustion handling covers short, empty and all-duplicate batches
- The reusable trigger hook keeps `StageColumn` lean

### 2. **AIB-890** (score: 90%)
- Best test coverage (unit, integration and E2E) and a clean pure helper module
- Lost points because the counter is hidden when the column is fully loaded and because of the ref-heavy hand-rolled loader

### 3. **AIB-891** (score: 77%)
- Could loop requests on an empty batch, and the counter is not always shown
- Has no integration or E2E tests

### 4. **AIB-892** (score: 66%)
- Has no drag pause, and polling fails with a 400 once more than 500 SHIP tickets are loaded
- Could loop requests on an empty batch
