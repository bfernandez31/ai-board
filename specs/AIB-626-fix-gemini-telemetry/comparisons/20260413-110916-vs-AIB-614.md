## Implementation Choices Analysis

### [Spec] US1-AC2: Thinking vs cache separation
| Ticket | Approach |
|--------|----------|
| AIB-626 | 5-category pricing (input, output, thinking, cacheRead, cacheCreation) with separate rates each |
| AIB-614 | 4-category pricing (input, output, thinking, cached). Cache read and creation merged into single "cached" rate; creation billed at input rate |

**Best**: AIB-626 - More granular separation aligns better with Google's actual pricing tiers.

### [Spec] US2-AC2: Cost accuracy across models
| Ticket | Approach |
|--------|----------|
| AIB-626 | Thinking priced at output rate ($10/M for 2.5 Pro), includes high-volume tier (>200K tokens) with adjusted pricing |
| AIB-614 | Thinking priced at $3.75/M for 2.5 Pro (appears incorrect vs Google pricing), no high-volume tier |

**Best**: AIB-626 - Thinking at output rate matches Google's published pricing. High-volume tier adds accuracy.

### Decision Point 1: Telemetry Merge Strategy
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-626 | `mergeTelemetryValue()` with DELTA/CUMULATIVE modes; Gemini defaults to CUMULATIVE (takes max) | Yes - handles Gemini's cumulative reporting model | Prevents double-counting; slightly more complex |
| AIB-614 | Simple additive merge (`(job.X || 0) + metrics.X`) for all agents | Partial - works for delta reporters, risks double-counting cumulative reporters | Simpler but may inflate Gemini metrics |

**Best**: AIB-626 - Gemini's stream file reports cumulative totals. Additive merge would double-count on repeated telemetry submissions.

### Decision Point 2: Agent Type Source of Truth
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-626 | `ALL_AGENTS` with `as const satisfies readonly Agent[]`, deriving `AGENT_FILTER_VALUES`, `NAMED_AGENTS`, `AGENT_LABELS`, `isSupportedAgent()`, `getAgentLabel()` | Yes - Principle I, strong types | Centralized, type-safe, reusable |
| AIB-614 | `Object.values(Agent)` from Prisma enum directly in each consumer | Partial - works but `as AgentFilter` casts reduce safety | Less abstraction, scattered usage |

**Best**: AIB-626 - Single source of truth with compile-time safety, avoids scattered `Object.values(Agent)` calls.

### Decision Point 3: Shell Script Telemetry Parsing
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-626 | Deep recursive `.. \| objects` jq traversal, multiple field name variants, GEMINI_MODEL fallback, cost_status determination, usageSnapshotMode field | N/A (shell) | Robust against nested/varied JSON structures |
| AIB-614 | Top-level `.[]` jq parsing, adds thinking/cache fields to existing pattern | N/A (shell) | Simpler, works for flat structures only |

**Best**: AIB-626 - More resilient to Gemini API response format variations.

### Decision Point 4: Scope of Type Updates
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-626 | Focused on core telemetry pipeline and analytics types only | Yes | Smaller blast radius |
| AIB-614 | Also updates comparison types (`TicketTelemetry`, `JobTelemetryData`, `TicketJobWithTelemetry`) | Yes | Broader but consistent |

**Best**: AIB-614 - Updating comparison types ensures thinkingTokens flows through the entire system.

## Ranking & Recommendation

### 1. **AIB-626** - Best code (score: 95%)
**Why it wins**:
- CUMULATIVE merge mode correctly handles Gemini's reporting semantics, preventing double-counting
- Gemini pricing accuracy (thinking at output rate, high-volume tier)
- Stronger type safety with `const satisfies` and centralized agent type source of truth
- Robust shell script parsing with deep JSON traversal
- Code quality improvements (Number.isNaN, explicit return types)

### 2. **AIB-614** - (score: 86%)
**Why it lost**:
- Additive-only merge risks double-counting Gemini cumulative telemetry
- Thinking token pricing at $3.75/M for 2.5 Pro doesn't match Google's published rate ($10/M)
- Weaker type safety with scattered `Object.values(Agent)` and `as AgentFilter` casts
- Broader scope (comparison types) is good but doesn't compensate for core accuracy issues

**Positives**:
- More unit test coverage for Gemini cost estimation (109-line dedicated test file)
- Updates comparison/telemetry types for full system consistency
- Exported `estimateGeminiCost` for testability
