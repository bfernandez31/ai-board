## Implementation Choices Analysis

### [Spec] Hybrid storage — no DB bloat
| Ticket | Approach |
|--------|----------|
| AIB-723 | Single `JobLog.content TEXT` column capped at 1 MB in Postgres. Not hybrid. |
| AIB-715 | **True hybrid**: gzipped NDJSON artifact on Vercel Blob + summary row in Postgres. SHA256 integrity via artifact header. |
| AIB-720 | Gzipped `artifactBytes BYTEA` in Postgres with SHA256. Compressed but still DB-resident. |
| AIB-721 | `rawContent TEXT` up to 5 MB in Postgres. Not hybrid. |

**Best**: AIB-715 — only one that offloads blobs out of Postgres, directly satisfying the "no multi-MB blobs in DB" acceptance criterion.

### [Spec] 30-day retention with auto-prune
| Ticket | Approach |
|--------|----------|
| AIB-723 | `pruneOldJobLogs()` exists but no cron/workflow wires it up. |
| AIB-715 | Dedicated `nightly-log-prune.yml` workflow + `/api/maintenance/prune-logs` endpoint. |
| AIB-720 | `retainedUntil` / `prunedAt` columns modelled, but pruning pathway is unclear. |
| AIB-721 | `/api/cron/prune-logs` endpoint + `pruneExpiredLogs` batched implementation. |

**Best**: AIB-715 and AIB-721 — both ship an actual trigger, not just a helper function.

### [Spec] Secret redaction (implicit from spec: logs must be safe to surface to members)
| Ticket | Approach |
|--------|----------|
| AIB-723 | None visible. |
| AIB-715 | `redactor.ts` with 8 regex families (GitHub PAT, Bearer, private keys, Anthropic/OpenAI/Google/Mistral keys, `*_TOKEN/SECRET/KEY` env vars). |
| AIB-720 | Inline `SENSITIVE_VALUE_PATTERN` (sk-/ghp_/Bearer) inside normalizer. |
| AIB-721 | None visible. |

**Best**: AIB-715 — dedicated, testable, broad-coverage redactor.

### Decision Point 1: Storage contract
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-723 | 1 MB TEXT in Postgres | OK | Simple but ignores spec's DB-bloat constraint. |
| AIB-715 | Vercel Blob (gzip NDJSON) + DB summary | Yes | Extra env dep (BLOB_READ_WRITE_TOKEN), but matches hybrid requirement. |
| AIB-720 | BYTEA + JSONB summary + SHA256 | OK | Heavier DB row, but integrity is strong. |
| AIB-721 | TEXT (5 MB) + entries JSON string | Borderline | `JSON.parse(entries)` at read time is awkward. |

**Best**: AIB-715 — only design that scales beyond tens of thousands of jobs without Postgres pressure.

### Decision Point 2: Ingestion idempotency
| Ticket | Approach |
|--------|----------|
| AIB-723 | `upsert` on unique `jobId` — safe on workflow retry. |
| AIB-715 | Upsert in `upsertJobExecutionLog` storage helper. |
| AIB-720 | Upsert-style persist with capturable-status check. |
| AIB-721 | Early-return "Log already exists" on duplicate — blocks re-upload, loses latest capture. |

**Best**: AIB-723 / AIB-715 / AIB-720 — upsert semantics match the workflow retry model.

### Decision Point 3: Job.logs legacy column
| Ticket | Approach |
|--------|----------|
| AIB-723 | Keeps column and mirrors summary to it. |
| AIB-715 | Leaves column untouched; summary lives in `JobLog.preview`. |
| AIB-720 | Leaves column untouched; summary lives in `summaryJson`. |
| AIB-721 | **Drops `Job.logs` column** in the migration and adds `logStatus`/`logSummary`. |

**Best**: AIB-721 — honest schema cleanup, but irreversible and couples this feature to a legacy cleanup.

### Decision Point 4: Schema versioning
| Ticket | Approach |
|--------|----------|
| AIB-723 | No versioning. |
| AIB-715 | Explicit `SCHEMA_VERSION = 1` + Zod schema (`schema.ts`). |
| AIB-720 | Zod request/response schemas, no artifact version field. |
| AIB-721 | No versioning. |

**Best**: AIB-715 — future-proof for format evolution.

## Ranking & Recommendation

### 1. **AIB-715** — (score: 90%)
**Why it wins**:
- Only true hybrid storage (Vercel Blob), directly meeting the DB-bloat acceptance criterion.
- Dedicated secret redactor with broad coverage.
- Automated retention via cron workflow.
- Highest test coverage: 11 tests + E2E spec.
- Schema-versioned artifact format for future evolution.

### 2. **AIB-721** — (score: 78%)
**Why it lost**:
- Stores up to 5 MB of raw content in Postgres TEXT — violates hybrid requirement.
- No secret redaction.
- Blocks re-upload on duplicate instead of upserting.

### 3. **AIB-720** — (score: 75%)
**Why it lost**:
- BYTEA in Postgres is compressed but still DB-resident.
- Touches `lib/telemetry/otlp-processor.ts` — telemetry regression surface.
- Retention trigger path unclear.

### 4. **AIB-723** (source) — (score: 62%)
**Why it lost**:
- Fails the hybrid-storage acceptance criterion outright.
- No secret redaction.
- Retention helper exists but no trigger.
- Lightest test coverage (3 tests).
