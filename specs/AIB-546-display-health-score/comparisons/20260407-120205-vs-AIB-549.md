## Implementation Choices Analysis

### [Spec] FR-006: Hover popover activation
| Ticket | Approach |
|--------|----------|
| AIB-546 | `useState` + `onMouseEnter`/`onMouseLeave` for hover-based Popover control |
| AIB-549 | Default Popover click behavior — no hover support |

**Best**: AIB-546 — Spec explicitly requires "Hovering over the heart MUST display a popover." AIB-549 uses click-to-open which violates FR-006.

### Decision Point 1: Transform function placement
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-546 | `toProjectWithCount()` in `app/lib/types/project.ts` with explicit param types | Yes | Co-located with type, but mixes types and logic |
| AIB-549 | `toProjectResponse()` in separate `app/lib/transforms/project.ts` using `ReturnType` inference | Yes | Better separation of concerns |

**Best**: AIB-549 — Cleaner separation; `ReturnType` inference stays in sync with Prisma query automatically.

### Decision Point 2: Heart color implementation
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-546 | Inline `hsl(var(--ctp-*))` strings with inline `style` for glow | Yes | Works but uses inline styles |
| AIB-549 | Tailwind `fill-ctp-*` classes + `drop-shadow-[...]` utility classes | Yes | Follows Tailwind-first approach per CLAUDE.md |

**Best**: AIB-549 — Uses static Tailwind classes, better aligned with CLAUDE.md color rules and purge safety.

### Decision Point 3: Health score type definition
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-546 | Inline object type within `ProjectWithCount` interface | Yes | Works, but requires `ProjectWithCount['healthScore']` extraction |
| AIB-549 | Named `ProjectHealthScore` interface, referenced by `ProjectWithCount` | Yes | Reusable, self-documenting |

**Best**: AIB-549 — Named interface is more ergonomic for consumers (e.g., component props).

### Decision Point 4: Score color utilities
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-546 | Imports `getScoreColorConfig` from `lib/health/score-calculator` | Yes | Reuses existing utility |
| AIB-549 | Imports `getScoreColor`/`getScoreThreshold` from `lib/quality-score` | Yes | Reuses existing utility |

**Best**: Tie — Both reuse existing codebase utilities.
