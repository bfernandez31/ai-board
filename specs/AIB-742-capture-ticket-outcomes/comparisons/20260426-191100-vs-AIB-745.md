## Implementation Choices Analysis

### [Spec] FR-006 frictionFree threshold + null handling
| Ticket | Approach |
|--------|----------|
| AIB-742 | `frictionJobCount===0 && qualityScore!==null && qualityScore>=75` — exactly per spec |
| AIB-745 | `qualityScore===null \|\| qualityScore>=80` — wrong threshold, treats null (QUICK) as friction-free |

**Best**: AIB-742 — spec explicitly forbids null-quality tickets being friction-free.

### [Spec] FR-002 capture must not block SHIP
| Ticket | Approach |
|--------|----------|
| AIB-742 | `void captureOutcomeOnShip(...).catch(...)` — fire-and-forget |
| AIB-745 | `await captureOutcomeForTicket(...)` inside try/catch — extends SHIP latency |

**Best**: AIB-742 — preserves SHIP-transition latency budget (SC-007 ≤ 50ms p95).

### [Spec] FR-003/FR-020 outcome row completeness
| Ticket | Approach |
|--------|----------|
| AIB-742 | 35-column model: tokens, ruleSetVersion, jobCountByPrefix, partialReason, workflowType, domain freq map, capturedAt |
| AIB-745 | 16-column model: cost+duration only, no tokens, no rule version, `filesTouched` is a count (not list), no partialReason |

**Best**: AIB-742 — spec consumers (analytics, prediction grounding) need the full set.

### [Spec] FR-021/FR-022 immutability
| Ticket | Approach |
|--------|----------|
| AIB-742 | Idempotency check + Zod validation; refuses second writes |
| AIB-745 | `prisma.ticketOutcome.upsert` with `update: { ...outcome, computedAt: new Date() }` and `force` option |

**Best**: AIB-742 — spec mandates first-write-wins; AIB-745 silently mutates on rerun.

### Decision Point: Diff fetching strategy
| Ticket | Approach | Trade-offs |
|--------|----------|-----------|
| AIB-742 | Per-commit `repos.getCommit` for each unique SHA, then dedupe | Works without branch; more requests; aggregates duplicates |
| AIB-745 | Single `repos.compareCommits(base, head)` per ticket | Cleaner, fewer API calls; depends on branch still existing |

**Best**: Mixed — AIB-745's approach is cleaner, but AIB-742's tolerates deleted branches by working from job `commitSha`.

### Decision Point: Validation layer
| Ticket | Approach |
|--------|----------|
| AIB-742 | Zod schema + `superRefine` invariants (counts add up, frictionFree implies threshold); P2002 caught silently |
| AIB-745 | Inline runtime checks; relies on Prisma types alone |

**Best**: AIB-742 — defensive validation catches inference bugs at the persistence boundary.

### Decision Point: Backfill orchestration
| Ticket | Approach |
|--------|----------|
| AIB-742 | Workflow dispatch + `BackfillProgress` table (status, cursor, version, error) + status route |
| AIB-745 | In-process loop with 200ms sleep, no progress table |

**Best**: AIB-742 — survives process restart, exposes status to operators (FR-015).

## Ranking & Recommendation

### 1. **AIB-742** — Best (89%)
- Full spec field coverage (rule version, partial reason, workflow type, token telemetry, freq map).
- Correct frictionFree contract (75 + null=false).
- Non-blocking SHIP path (fire-and-forget with logging).
- Workflow-driven, resumable backfill via `BackfillProgress`.
- Strong validation (Zod + superRefine), 10 test files.

### 2. **AIB-745** — (69%)
- Cleaner diff API (`compareCommits`) and fewer files, but
- Wrong friction-free threshold + null semantics (FR-006 violation).
- Missing ruleSetVersion, partialReason, workflowType columns.
- `force`/upsert update path violates immutability (FR-021/FR-022).
- Fewer tests; awaits inline so SHIP latency is exposed to capture failures.
