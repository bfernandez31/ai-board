## Design Details

### 1. run-command.sh (NEW)

**Purpose**: Look up a command key in `.ai-board/config.yml` and execute it in the target directory.

**Contract**: See [contracts/run-command-sh.md](./contracts/run-command-sh.md)

**Implementation approach**:
```bash
#!/bin/bash
set -euo pipefail

TARGET_DIR="$1"
COMMAND_KEY="$2"
CONFIG="${TARGET_DIR}/.ai-board/config.yml"

# Missing config = no-op
[[ ! -f "$CONFIG" ]] && exit 0

# Bootstrap yq if needed
ensure_yq()  # shared with setup-environment.sh

# Read command
CMD=$(yq eval ".commands.${COMMAND_KEY}" "$CONFIG")
[[ "$CMD" == "null" || -z "$CMD" ]] && exit 0

# Execute in target directory
cd "$TARGET_DIR"
eval "$CMD"
```

### 2. setup-environment.sh Modifications

**Purpose**: Add `--phase` parameter to support lightweight (specify/plan) and full (implement/verify) execution tiers.

**Contract**: See [contracts/setup-environment-sh.md](./contracts/setup-environment-sh.md)

**Changes**:
- Parse optional `--phase <lightweight|full>` argument (default: `full`)
- Wrap dependency install, agent CLI, env export, Prisma, Playwright sections in `if [[ "$PHASE" == "full" ]]` guards
- Adjust final validation to skip node_modules and agent CLI checks in lightweight mode
- Add error for unrecognized phase values

### 3. Workflow Modifications

**Pattern applied to all 6 workflows**:

a. **Add service inputs**: `needs_postgres`, `needs_redis`, `needs_mysql`, `needs_mongo` + version inputs
b. **Add conditional services block**: Using empty-image-string pattern for conditional provisioning
c. **Replace hardcoded commands**: `bun install` → `run-command.sh target install`, `bun run test:unit` → `run-command.sh target test_unit`, etc.
d. **Call setup-environment.sh**: With `--phase lightweight` for specify/plan, `--phase full` for implement/verify/build
e. **Keep infrastructure commands hardcoded**: Prisma generate/migrate, Playwright browser install, bun cache

**Per-workflow specifics**:

| Workflow | Phase | Services | Commands to Replace |
|----------|-------|----------|-------------------|
| speckit.yml | lightweight (specify/plan), full (implement) | postgres, redis, mysql, mongo | `bun install --frozen-lockfile` |
| quick-impl.yml | full | all four | `bun install --frozen-lockfile` |
| verify.yml | full | all four | `bun install --frozen-lockfile`, `bun run test:unit`, `npx playwright test` |
| health-scan.yml | full (TESTS), lightweight (others) | all four | `bun install --frozen-lockfile` |
| iterate.yml | lightweight | none | none (add setup-environment.sh call) |
| ai-board-assist.yml | lightweight | none | implicit bun commands |

### 4. Backward Compatibility

- `run-command.sh` exits 0 when config is missing → workflows work for non-onboarded repos
- `setup-environment.sh --phase full` is the default → existing callers unaffected
- Service inputs default to `false` → no services provisioned unless explicitly requested
- ai-board's own `config.yml` already has all command keys → self-management unaffected

## Testing Strategy

| Test Type | Location | What It Covers |
|-----------|----------|----------------|
| Unit test | `tests/unit/scripts/run-command.test.ts` | run-command.sh: missing config (exit 0), missing key (exit 0), valid command (executes + returns exit code), invalid YAML (exit 1) |
| Manual validation | CI workflow runs | Trigger speckit.yml with command=specify and command=implement to verify phase-aware setup |
| Manual validation | CI workflow runs | Trigger verify.yml to confirm test commands are read from config |

**Decision tree applied**:
- run-command.sh is a pure function (input → exit code) → **Unit test** with Vitest spawning the shell script
- Workflow YAML changes require real GitHub Actions → **Manual validation** (cannot be unit tested)
- No React components, no API endpoints, no browser requirements

**Critical rules compliance**:
- ✅ API tests use Vitest, NOT Playwright
- ✅ E2E is expensive — no E2E tests for shell scripts
- ✅ Search existing tests FIRST — no existing script tests to extend
