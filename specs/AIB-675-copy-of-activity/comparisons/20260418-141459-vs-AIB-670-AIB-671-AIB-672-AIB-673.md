## Implementation Choices Analysis

### Decision Point 1: Intensity Scale Strategy
| Ticket | Approach |
|--------|----------|
| AIB-675 | Fixed thresholds (1, 2, 5, 9) — predictable, test-friendly |
| AIB-670 | Max-count normalization at render time |
| AIB-671 | Max-count normalization at render time |
| AIB-672 | Quartile thresholds pre-computed server-side (extra payload) |
| AIB-673 | Max-count normalization at render time |

**Best**: AIB-675 — deterministic thresholds are simpler to verify and don't re-rank cells as data grows.

### Decision Point 2: Module Organization
| Ticket | Approach |
|--------|----------|
| AIB-675 | Consistent `lib/activity-heatmap/{types,period,grid,queries}.ts` + `components/projects/activity-heatmap.tsx` |
| AIB-670 | Split across `lib/analytics/activity-heatmap*.ts` + `components/activity-heatmap/` |
| AIB-671 | Clean `lib/activity-heatmap/` but grid logic lives inline in component |
| AIB-672 | `lib/analytics/activity-heatmap*.ts` + timezone helper |
| AIB-673 | Fragmented `lib/heatmap/*` + `components/heatmap/*` (no `activity-` prefix) |

**Best**: AIB-675 — coherent namespace, each concern in its own file, clearly reusable.

### Decision Point 3: Agent Enum Source
| Ticket | Approach |
|--------|----------|
| AIB-675 | Zod validates against shared `HeatmapAgentFilter` type guard |
| AIB-670 | **Hardcodes** agent enum values in route-local Zod schema |
| AIB-671 | Reuses `AGENT_FILTER_VALUES` constant from `lib/analytics/types` |
| AIB-672 | Reuses `AGENT_FILTER_VALUES` constant |
| AIB-673 | Parses agent from query param with custom type guard |

**Best**: AIB-671/AIB-675 — no duplication; AIB-670 creates maintenance debt.

### Decision Point 4: Tooltip Primitive
| Ticket | Approach |
|--------|----------|
| AIB-675 | shadcn/ui `<Tooltip>` (Radix) for desktop, dialog-like for mobile |
| AIB-670 | shadcn/ui `<Tooltip>` |
| AIB-671 | shadcn/ui `<Tooltip>` desktop + popover mobile, `hidden sm:block` split |
| AIB-672 | shadcn/ui `<Tooltip>` |
| AIB-673 | **Manual** `activeCell` state + `useEffect` click-outside handler |

**Best**: AIB-675/AIB-671 — Radix primitives handle a11y, focus, and dismiss correctly. AIB-673's manual logic is a bug surface.

### Decision Point 5: URL Param Naming
| Ticket | Approach |
|--------|----------|
| AIB-675 | `heatmap-period`, `heatmap-agent` (kebab-case, namespaced) |
| AIB-670 | `heatmapAgent`, `heatmapYear` (camelCase, mixed with `year` concept) |
| AIB-671 | `hm-period`, `hm-agent` (abbreviated) |
| AIB-672 | `hm-period`, `hm-agent` |
| AIB-673 | `heatmapPeriod`, `heatmapAgent` |

**Best**: AIB-675 — readable and consistent with Next.js URL convention.

## Ranking & Recommendation

### 1. **AIB-675** — Best code (score: 93%)
**Why it wins**:
- Coherent `activity-heatmap/` namespace across lib + component
- Fixed intensity thresholds — deterministic and testable
- Zod validation against shared type guard (no duplicate enums)
- Clean kebab-case URL params

### 2. **AIB-671** — (score: 90%)
**Why it lost**:
- Agent enum reuse is good, but grid math lives inline in the component
- Slightly less modular than AIB-675; abbreviated `hm-*` URL params

### 3. **AIB-670** — (score: 87%)
**Why it lost**:
- Hardcoded agent enum in the API route (coupling to future agent changes)
- Only 6 source files vs. 4 test files — strong coverage, but less feature surface

### 4. **AIB-672** — (score: 83%)
**Why it lost**:
- Timezone-aware bucketing adds complexity the spec doesn't require
- Server-computed quartile intensity adds payload without clear benefit
- Highest cost ($32.80) / iterations (5 jobs) — likely from scope creep

### 5. **AIB-673** — (score: 81%)
**Why it lost**:
- Manual tooltip state (vs. Radix primitives) increases bug surface
- Fragmented `lib/heatmap/` + `components/heatmap/` namespace (inconsistent with `activity-` prefix used elsewhere)
