# Implementation Plan: Project Onboarding — Hybrid Workflow

**Branch**: `AIB-575-project-onboarding-hybrid` | **Date**: 2026-04-08 | **Spec**: `specs/AIB-575-project-onboarding-hybrid/spec.md`
**Input**: Feature specification from `/specs/AIB-575-project-onboarding-hybrid/spec.md`

## Summary

Replace the stub `onboard.yml` workflow with a real two-phase hybrid onboarding pipeline. Phase 1 is a deterministic bash script (`detect-stack.sh`) that scans manifest files, lockfiles, and config patterns to produce a validated `.ai-board/config.yml` and `analysis.json`. Phase 2 invokes an LLM agent via `run-agent.sh` to generate project-specific `CLAUDE.md` and `constitution.md` files. The workflow supports partial success (Phase 1 committed even if Phase 2 fails) and reports structured artifact summaries via the existing setup job callback API.

## Implementation Phases

### Phase 1: Config Schema Extensions (TypeScript)

**Pattern reference**: Existing enum definitions at `lib/validations/config.ts:11-44`. Additive change — append values to `z.enum([...])` arrays.

### Phase 2: Stack Detection Script (Bash)

Create `.github/scripts/detect-stack.sh` — deterministic bash script that scans a repository and produces `config.yml` + `analysis.json`.

**Detection strategy** (from FR-002 through FR-007):
1. Scan for manifest files → determine primary language
2. Scan for lockfiles → determine package manager
3. Parse manifests for dependency names → determine framework and test framework
4. Scan for `docker-compose.yml` and ORM configs → determine services
5. Extract commands from `package.json` scripts, `Makefile`, `Taskfile`, `pyproject.toml`
6. Assemble `config.yml` (validated against schema structure) and `analysis.json`

**Input**: `$1` = path to target repository root
**Output**: `$1/.ai-board/config.yml`, `$1/analysis.json`
**Exit codes**: 0 = success, 1 = detection failure

**Key design decisions**:
- Primary language determined by root-level manifest priority: `package.json` > `Cargo.toml` > `go.mod` > `pyproject.toml` > `pom.xml`/`build.gradle` > `Gemfile` > `composer.json`
- Multiple manifests → primary = first match, secondary languages recorded in `analysis.json`
- Empty repo (no manifests) → minimal config with `language: null`, project name from directory
- YAML generation uses `cat <<EOF` (no external YAML library needed for simple structure)

**Pattern reference**: Follow error handling from `.claude-plugin/scripts/bash/common.sh` — `set -euo pipefail`, `get_repo_root()` style validation.

### Phase 3: Agent Command File

Create `.claude-plugin/commands/ai-board.onboard.md` — prompt for the LLM agent to generate CLAUDE.md and constitution.md.

See `workflows/onboard-command.md` for full specification. The command file is a markdown prompt that instructs the agent on:
- How to read and use `analysis.json`
- Content requirements for CLAUDE.md (FR-017)
- Content requirements for constitution.md (FR-018)
- AGENTS.md symlink creation (FR-011)
- analysis.json cleanup

See `workflows/onboard-workflow.md` for full specification. Key implementation points:
