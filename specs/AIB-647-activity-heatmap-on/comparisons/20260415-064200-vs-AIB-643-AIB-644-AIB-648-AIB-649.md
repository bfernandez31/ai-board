## Implementation Choices Analysis

### [Spec] Empty state display
| Ticket | Approach |
|--------|----------|
| AIB-647 | Shows "No activity in this period" centered text inside grid container |
| AIB-643 | No explicit empty state — grid renders but no empty message |
| AIB-644 | Dashed-border empty state box with "No matching workspace activity" message |
| AIB-648 | No dedicated empty state handling |
| AIB-649 | Grid renders with all-zero cells, no explicit message |

**Best**: AIB-644 — Dedicated empty state component with dashed border, most polished UX.

### [Spec] Agent filter with effective agent resolution
| Ticket | Approach |
|--------|----------|
| AIB-647 | `buildEffectiveAgentWhere` with OR clause for ticket.agent / project.defaultAgent |
| AIB-643 | Same effective agent pattern via Prisma OR clause |
| AIB-644 | `resolveEffectiveAgent` + `matchesAgent` with in-memory filtering after fetch |
| AIB-648 | Simple `ticket.agent` filter only — misses project.defaultAgent fallback |
| AIB-649 | `buildAgentWhere` + `buildTicketAgentWhere` — proper OR clause in Prisma |

**Best**: AIB-647/AIB-649 — Database-level effective agent filtering is most efficient.

### [Spec] Shipped ticket determination
| Ticket | Approach |
|--------|----------|
| AIB-647 | Queries `ship` command jobs with COMPLETED status — matches spec FR-020 |
| AIB-643 | Uses `ticket.stage = SHIP` + `updatedAt` — deviates from spec |
| AIB-644 | Uses `ticket.stage = SHIP` + `updatedAt` — deviates from spec |
| AIB-648 | Uses `closedAt` with SHIP/CLOSED stages — non-standard |
| AIB-649 | Uses `ticket.stage = SHIP` + `updatedAt` — deviates from spec |

**Best**: AIB-647 — Only implementation that matches the spec's FR-020 requirement to use ship command job completion.

## Ranking & Recommendation

### 1. **AIB-644** — Best code (score: 92%)
**Why it wins**:
- Server-side pre-rendering with `initialData` eliminates loading flash — best UX
- 4 test files including E2E test (50% test ratio) — highest test coverage
- URL state sync with `useRouter` + `useSearchParams` enables shareable filter states
- Rich pre-computed response with legend buckets, view options, summary stat cards
- Multi-hue `ctp-*` color palette matches project aurora theme
- `isValidActivityHeatmapYearView` validation, `buildActivityHeatmapErrorResponse` error builder

### 2. **AIB-647** — Source (score: 89%)
**Why it placed second**:
- Best component decomposition (6 components in feature folder) per constitution II
- Only ticket implementing FR-020 correctly (shipped via ship job completion)
- Sticky day labels on mobile scroll
- Slightly lower test coverage (15% ratio, 2 files)

### 3. **AIB-649** — (score: 84%)
**Why it placed third**:
- Clean `parseProjectActivityFilters` validation pattern
- SSR initial data + thinnest API route
- `isOutsidePeriod` edge cell handling is a nice touch
- Proper effective agent resolution

### 4. **AIB-643** — (score: 80%)
**Why it placed fourth**:
- Hook placed in `/hooks/` instead of `/app/lib/hooks/queries/` (non-standard)
- No explicit empty state message
- No sticky day labels on mobile
- Solid but less polished than top 3

### 5. **AIB-648** — (score: 69%)
**Why it placed last**:
- All API logic embedded in 203-line route file (violates separation of concerns)
- Exports types from API route (anti-pattern in Next.js)
- Agent filter uses simple `ticket.agent` — misses effective agent resolution via project.defaultAgent
- No `refetchInterval` (uses 1min staleTime only, missing 15s polling per CLAUDE.md)
- Uses `closedAt` for shipped counting (non-standard)
