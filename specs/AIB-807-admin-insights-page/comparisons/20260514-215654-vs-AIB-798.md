- **Tickets Evaluated**: AIB-807 (source), AIB-798

**Critical gap in AIB-798**: `RunAnalysisButton` posts `retryPeriod` in the body, but the trigger route never reads the request body — `periodStart` and `periodEnd` are recomputed (`prevEnd ?? earliest ?? now` and `new Date()`). The visible "Reessayer" button works, but it does NOT retry the same window. This silently violates FR-016 and the entire P2 user-story rationale.

## Implementation Choices Analysis

### [Spec] FR-016 — Retry scope (same window)
| Ticket | Approach |
|---|---|
| AIB-807 | Zod schema validates optional `periodStart`/`periodEnd`; when both present, skips fresh-window preflight and uses the provided window verbatim. |
| AIB-798 | Client serializes `retryPeriod` into the POST body, but the server ignores it and recomputes the window. |

**Best**: AIB-807 — only implementation that fulfills the spec.

### [Spec] FR-011 — Readable failure presentation
| Ticket | Approach |
|---|---|
| AIB-807 | Inline FAILED branch inside `insights-report-view.tsx`: reuses existing `ReportErrorPlaceholder` plus inline link + retry button. |
| AIB-798 | Dedicated `FailureDiagnosticsPanel` component with explicit fallback text ("Run failed without a recorded reason…") and isolated unit test. |

**Best**: AIB-798 — better separation, dedicated tests, more graceful empty-reason handling.

### Decision Point: GitHub URL composition
| Ticket | Approach | Notes |
|---|---|---|
| AIB-807 | `buildGithubActionsUrl` exported from `app/lib/insights/repository.ts`; env resolution at page-component level (`process.env.GITHUB_OWNER/REPO`). | Couples URL helper with data-access module. |
| AIB-798 | Standalone `lib/admin/insights-github-url.ts` with own unit test; validates numeric workflowRunId; falls back to env if owner/repo absent. | Better separation, defensive numeric check. |

**Best**: AIB-798 — more idiomatic and independently testable.

### Decision Point: List/Table component shape
| Ticket | Approach |
|---|---|
| AIB-807 | Inline `<ul>` inside `insights-report-view.tsx`; `formatDuration`/`compactPeriod` declared as private helpers. |
| AIB-798 | Dedicated `PastReportsTable` with exported `formatCompactPeriod`, `formatCompactDuration`, `formatDateFull` (each unit-tested), 4-column grid with header row, `max-h-[70vh]` scroll. |

**Best**: AIB-798 — more reusable, denser visual layout, far more test coverage on formatters.

### Decision Point: Retry trigger label
| Ticket | Label | Notes |
|---|---|---|
| AIB-807 | "Retry analysis" (English, consistent with rest of UI) | OK |
| AIB-798 | "Reessayer" (French) hard-coded in `FailureDiagnosticsPanel` | Inconsistent UI language; rest of app is English. |

**Best**: AIB-807.

### Decision Point: New API routes
| Ticket | Approach |
|---|---|
| AIB-807 | Adds `GET /api/admin/insights/reports` and `GET /api/admin/insights/reports/[id]` plus integration tests, enabling cleaner client refresh. |
| AIB-798 | No new API routes — relies on existing data-fetch hook flow. |

**Best**: AIB-807 — better REST surface; explicit integration coverage. (Not strictly required by spec; could be considered over-engineering depending on actual hook usage.)

## Ranking & Recommendation

### 1. **AIB-807** — score 83%
**Why it wins**:
- Only implementation that actually fulfills FR-016 (retry on same window) — the centerpiece of US2.
- Zod-validated retry endpoint (Constitution IV. Security-First).
- Cleaner request semantics: explicit retry vs fresh-run code path on the server.
- Adds dedicated `/reports` and `/reports/[id]` API routes with integration tests.

### 2. **AIB-798** — score 81.5%
**Why it lost**:
- Silently violates FR-016: client passes `retryPeriod`, server ignores it. The "retry" button computes a fresh window instead.
- French "Reessayer" label in an otherwise English UI.
- Trigger endpoint never parses the request body — no Zod, no validation, no safety on the new contract.

**Strengths worth backporting** (in a follow-up on the AIB-807 branch):
- `FailureDiagnosticsPanel` component + its unit test.
- `lib/admin/insights-github-url.ts` helper + its unit test.
- `PastReportsTable` with exported formatting helpers + their tests.
- E2E `tests/e2e/admin/insights-flow.spec.ts`.
