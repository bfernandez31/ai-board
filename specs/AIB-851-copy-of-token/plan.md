# Implementation Plan: Token Saving via RTK + Unified Per-Ticket Run Settings

**Branch**: `AIB-851-copy-of-token` | **Date**: 2026-06-04 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/AIB-851-copy-of-token/spec.md`

## Summary

Add project-level and per-ticket token saving settings (via RTK compression for Claude agent runs), consolidate per-ticket overrides (agent, models, policy, token saving) into a unified "Run settings" dialog, and streamline the kebab menu from 5 to 3 items. Token saving follows the existing nullable override pattern (ticket > project > OFF), RTK activates as a Claude Code PreToolUse hook with graceful fallback, and each job records its token saving status for telemetry comparison.

## Implementation Phases

### Phase 1: Database + API Foundation
**Goal**: Token saving fields exist in DB and are accepted by all relevant APIs.

1. **Prisma migration**: Add `tokenSaving Boolean @default(false)` to Project, `tokenSaving Boolean?` to Ticket, `tokenSavingStatus String? @db.VarChar(20)` to Job
2. **Validation schemas**: Add `tokenSaving` to `projectUpdateSchema` (clarification-policy.ts), `patchTicketSchema` (lib/validations/ticket.ts), `ticketResponseSchema`
3. **Project API** (app/api/projects/[projectId]/route.ts): Accept and persist `tokenSaving` in PATCH
4. **Ticket API** (app/api/projects/[projectId]/tickets/[id]/route.ts): Accept `tokenSaving` in PATCH, return in GET (include `project.tokenSaving` in response)
5. **Job status API**: Accept `tokenSavingStatus` in PATCH /api/jobs/[id]/status
6. **Clone/copy**: Extend `duplicateTicket()` and `fullCloneTicket()` in lib/db/tickets.ts to copy `tokenSaving` field; extend `serializeTicket()` in duplicate route
7. **Tests**: Extend `tests/integration/projects/settings.test.ts` (project toggle), `tests/integration/tickets/duplicate.test.ts` (clone preservation)

### Phase 2: Workflow Dispatch + RTK Integration
**Goal**: Token saving setting reaches the runner and RTK is activated for Claude runs.

1. **Resolution function**: Add `resolveEffectiveTokenSaving()` to transition.ts following `resolveEffectiveAgent()` pattern
2. **Dispatch inputs**: Pass `token_saving: 'true'` in workflow inputs when effective token saving is ON, across all dispatch paths (speckit, quick-impl, verify, iterate)
3. **Workflow YAML**: Add `token_saving` input to speckit.yml, quick-impl.yml, verify.yml, iterate.yml; map to `TOKEN_SAVING` env var
4. **run-agent.sh**: Add RTK installation and activation block before Claude invocation (after line ~457). Guard on `TOKEN_SAVING=true && AGENT=CLAUDE`. Report status via PATCH callback (best-effort).
5. **Tests**: Add token saving resolution tests to `tests/unit/workflows/model-resolution.test.ts`

### Phase 3: Project Settings UI
**Goal**: Project owners can toggle token saving in project settings.

1. **TokenSavingCard** (components/settings/token-saving-card.tsx): New client component following ClarificationPolicyCard pattern. Toggle switch (shadcn Switch component), description text, owner-only editability.
2. **Settings page**: Add TokenSavingCard to `app/projects/[projectId]/settings/page.tsx` after existing cards
3. **Tests**: RTL component test for TokenSavingCard (can be added to existing settings test file or as a focused unit test)

### Phase 4: Unified Run Settings Dialog
**Goal**: Single "Run settings" dialog replaces three separate dialogs.

1. **RunSettingsDialog** (components/tickets/run-settings-dialog.tsx): New client component using shadcn Tabs with four tab panels — Agent, Models, Clarification Policy, Token Saving. Each tab panel composes the logic from the existing dialog components (reuse handlers, not the Dialog wrappers). Stage-aware editability: Agent and Policy tabs are read-only when ticket is not INBOX.
2. **Token Saving section**: Switch component with three states via Select ("Use project default", "Force ON", "Force OFF"). Shows inherited value.
3. **Ticket detail modal**: Replace `policyEditOpen`, `agentEditOpen`, `modelOverrideOpen` states with single `runSettingsOpen`. Replace 3 DropdownMenuItem items (Edit Policy, Edit Agent, Edit Models) with 1 "Run settings" item. Remove rendering of 3 separate dialogs, render RunSettingsDialog instead.
4. **Tests**: Extend `tests/unit/components/ticket-detail-modal.test.tsx` — verify kebab menu has exactly 3 items, RunSettingsDialog opens/closes, each section is present

### Phase 5: Token Saving Badge + Job Display
**Goal**: Visual indicators for token saving in ticket header and job details.

1. **TokenSavingBadge** (components/ui/token-saving-badge.tsx): Small component following PolicyBadge pattern. Zap icon (from lucide-react), tooltip showing source (override vs project default). Only rendered when effective token saving is ON.
2. **Ticket header strip**: Add TokenSavingBadge to ticket-detail-modal.tsx header strip (after agent badge, before branch link)
3. **Job details**: Display `tokenSavingStatus` in job detail/telemetry view with appropriate label and styling (Active = green, Inactive = muted, Fallback = amber, N/A = hidden)
4. **Tests**: Unit test for TokenSavingBadge rendering
