## Implementation Choices Analysis

### [Spec] Stripe webhook outcome capture (FR-007)
| Ticket | Approach |
|--------|----------|
| AIB-800 | Adds `WebhookOutcome` Prisma model + `recordWebhookOutcome()` invoked from `app/api/webhooks/stripe/route.ts` on every success/failure. Direct, queryable data source. |
| AIB-797 | No model, no recording. Alert detector infers failure when "subscription transitions happened but no recent StripeEvent rows." Misses retries-exhausted and non-mutating events; cannot answer "what failed?". |

**Best**: AIB-800 — only one that truly fulfills the spec's tracking obligation.

### [Spec] Critical cron allowlist (FR-008/009)
| Ticket | Approach |
|--------|----------|
| AIB-800 | `CriticalCron` Prisma enum + `CronRun` model; new `billing-reconcile.yml` workflow plus heartbeat steps in nightly-health + nightly-log-prune. Three crons registered. |
| AIB-797 | `CronRunLog` table + `cron-markers` POST endpoint; only `nightly-health` and `nightly-log-prune` instrumented. No billing-reconcile workflow despite spec listing billing reconciliation as a canonical critical cron. |

**Best**: AIB-800 — wider allowlist matches the spec example list.

### Decision Point: State management for refresh
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-800 | `useQuery` with `keepPreviousData` + `refetchInterval: 30_000` directly in component | Yes (TanStack Query) | Minimal indirection |
| AIB-797 | Dedicated `useAdminHomeSnapshot` hook + retry CTA card | Yes (TanStack Query) | Nicer error UX, slightly more surface |

**Best**: AIB-797 by a hair on UX (retry CTA), AIB-800 simpler.

### Decision Point: Module layout
| Ticket | Approach | Notes |

| AIB-797 | Business logic under `app/lib/admin/home/*` | Diverges from `lib/admin/insights/*` precedent |

**Best**: AIB-800 — follows established codebase layout.

## Ranking & Recommendation

### 1. **AIB-800** — Best code (score: 88%)
**Why it wins**:
- Direct, testable fulfillment of FR-007 with a `WebhookOutcome` model and write at the webhook boundary.
- Wider, schema-enforced critical-cron allowlist (enum) plus the missing `billing-reconcile.yml` workflow.
- Adds an E2E spec on top of unit + integration coverage.
- Code lives under `lib/admin/home/*`, matching existing admin utilities (e.g. `lib/admin/insights/*`).

### 2. **AIB-797** — (score: 78%)
**Why it lost**:
- Replaces FR-007's explicit outcome capture with a heuristic that will silently miss webhook failures whose Stripe event row was never written.
- Critical-cron allowlist hardcoded to two entries; no billing-reconcile workflow.
- No E2E coverage of the new surface.
- Slightly nicer retry-on-error UX is not enough to offset the FR-007 gap.
