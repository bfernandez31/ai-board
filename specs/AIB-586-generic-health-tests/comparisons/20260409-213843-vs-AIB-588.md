## Implementation Choices Analysis

### [Spec] Scripts invoked from ai-board plugin checkout path (FR-010)
| Ticket | Approach |
|--------|----------|
| AIB-586 | Creates new scripts at `.claude-plugin/scripts/bash/run-health-tests.sh` and `run-tests-with-reports.sh` — literally inside the plugin directory |
| AIB-588 | Refactors existing `scripts/run-health-tests.sh` and `scripts/run-tests-with-reports.sh` in-place at repo root, changes workflow `working-directory` to ai-board checkout |

**Best**: AIB-586 — Spec explicitly states "Generic Test Orchestrator (run-health-tests.sh **in plugin**)" and "Generic Test Runner (run-tests-with-reports.sh **in plugin**)". AIB-586 places both in `.claude-plugin/scripts/bash/` as specified.

### [Spec] Multi-framework parser support (FR-005)
| Ticket | Approach |
|--------|----------|
| AIB-586 | Dedicated parser functions for 8 frameworks: `parse_vitest_report`, `parse_playwright_report`, `parse_pytest_report`, `parse_cargo_report`, `parse_go_report`, `parse_rspec_report`, `parse_phpunit_report`, plus `parse_exitcode_report` fallback |
| AIB-588 | Refactors existing scripts (net -87 lines in run-tests-with-reports.sh), relies on existing parser logic with config-driven command selection |

**Best**: AIB-586 — More explicit and comprehensive parser implementations covering all 5+ required frameworks with clear function boundaries and fallback strategy.

### [Spec] SKIPPED scan API handling (US3)
| Ticket | Approach |
|--------|----------|
| AIB-586 | Writes SKIPPED result JSON from bash script; workflow removes the defensive guard that prevented TESTS from being SKIPPED |
| AIB-588 | Full stack: bash writes SKIPPED result, API route validates `skipReason` required for TESTS SKIPPED, removes COMPLIANCE-only coercion, integration test for SKIPPED flow |

**Best**: AIB-588 — Handles SKIPPED at both script and API level with proper validation, ensuring data integrity.

### Decision Point 1: Config Schema Validation
| Ticket | Approach | Constitution | Trade-offs |
|--------|----------|--------------|------------|
| AIB-586 | Adds `testing` section to config.yml; no Zod schema for new fields | Partial (I) | Faster to implement, but new config fields lack TypeScript validation |
| AIB-588 | Adds `TestCapabilitiesSectionSchema` with Zod, `superRefine` cross-field validation (primaryCommandKey must reference configured command), TypeScript types | Yes (I) | More robust, catches misconfiguration at parse time |

**Best**: AIB-588 — TypeScript-first approach (Constitution Principle I) with Zod schemas and cross-field validation prevents invalid configurations.
