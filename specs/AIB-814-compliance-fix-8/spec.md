# Quick Implementation: [Compliance] Fix 8 violations - admin scaffolding cleanup + Card adoption

**Feature Branch**: `AIB-814-compliance-fix-8`
**Created**: 2026-05-15
**Mode**: Quick Implementation (bypassing formal specification)

## Description

Merges AIB-803, AIB-804, AIB-805, and AIB-808 — 8 health-scan compliance violations across the admin feature, grouped by root cause.

## Group A — Stale/duplicate admin scaffolding (3 violations, 3 principles)

Two modules shadow canonical implementations that already exist elsewhere. Removing the dead code clears three separate principle violations at once.

- **Security-First Design** (was AIB-804) — `lib/admin/access-control.ts:7`: mock `auth()` always returns `{ user: null }`. The real admin gate is `requireAdminOrNotFound` in `app/lib/auth/admin.ts`. Any caller importing from this stale module silently denies every admin — security footgun next to the real implementation.
- **TypeScript-First Development** (was AIB-805) — `lib/admin/access-control.ts:24` (`getCurrentUser`) and `:29` (`requireAdminAccess`) are missing explicit return-type annotations. Resolved automatically if the file is removed; otherwise must be typed.
- **Component-Driven Architecture** (was AIB-803) — `lib/types/insights.ts:5` defines an `InsightsReport` interface (string id, `analysisType`, `metadata`…) that conflicts with the canonical `InsightsReport` generated by Prisma (`@prisma/client`) and used throughout admin-insights (number id, `status: InsightsRunStatus`, `periodStart/periodEnd`, `sessionsCount`…). The duplicate is consumed only by `components/admin/insights-page.tsx` and `components/admin/report-list.tsx`, which themselves duplicate the real `components/admin/insights/insights-report-view.tsx` and are not wired into any route.

## Group B — shadcn/ui Card adoption in admin/home (4 violations, 1 principle)

**Component-Driven Architecture** (was AIB-808) — four files under `components/admin/home/` reconstruct card surfaces manually with `<div className="rounded-lg border bg-card p-4">` instead of composing the shadcn/ui `<Card>` primitive that sibling `components/admin/insights/*` already uses:

- `components/admin/home/pulse-tile.tsx:24` — 1 card
- `components/admin/home/business-row.tsx:19` — 3 cards (Plan distribution, 30-day activation funnel, Churn this month)
- `components/admin/home/details-grid.tsx:20` — 4 cards (New paying users, Recent cancellations, Top users, Top projects)
- `components/admin/home/trends-row.tsx:19` — 3 cards (Signups, Jobs, MRR)

## Acceptance criteria

- `lib/admin/access-control.ts` is removed, or rewritten to re-export `requireAdminOrNotFound` with explicit return types and no mock `auth()`.
- `lib/types/insights.ts` no longer defines a competing `InsightsReport`; admin-insights surfaces continue to compile against `@prisma/client`.
- Unused duplicate components `components/admin/insights-page.tsx` and `components/admin/report-list.tsx` are removed (no route consumes them).
- All admin/home card surfaces compose `<Card>` / `<CardContent>` from `components/ui/card.tsx`.
- The next health scan reports zero of the original 8 violations across the four principles.
- `bun run type-check` and `bun run lint` pass.

Supersedes: AIB-803, AIB-804, AIB-805, AIB-808.
