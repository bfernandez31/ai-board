## Implementation Choices Analysis

### [Spec] Server-rendered initial data (FR-011)
| Ticket  | Approach                                                                                 |
|---------|------------------------------------------------------------------------------------------|
| AIB-702 | Pure `async` Server Component — data fetched server-side, no hydration spinner           |
| AIB-692 | Client Component with TanStack `initialData` + refetchInterval 60s (hydration flash risk)|
| AIB-694 | Client Component + period-based filter; uses `initialData` prop                          |
| AIB-701 | Client Component + `initialData`; ScrollArea wrapper                                     |

**Best**: AIB-702 — only implementation that truly avoids a loading flash.

## Ranking & Recommendation

### 1. **AIB-702** — Best code (score: **88%**)
**Why it wins**:
- Only implementation using a true Server Component (FR-011 satisfied by design, not by convention)
- Cleanly decomposed into 4 focused components following Constitution §II
- Includes Playwright e2e test on top of integration + unit coverage
- Aurora theming per CLAUDE.md, no hardcoded colors
- Preserves spec's `year` semantics instead of substituting a generic period enum

### 2. **AIB-701** — (score: 73%)
**Why it lost**:
- Client-only, loading flash possible
- Modifies shared `lib/db/users.ts` (scope creep)
- 335-line monolithic component

### 3. **AIB-692** — (score: 72%)
**Why it lost**:
- Single 299-line client component, no sub-component split
- Unnecessary `refetchInterval: 60000` (spec asks for SSR, not polling)

### 4. **AIB-694** — (score: 65%)
**Why it lost**:
- 423-line monolithic client component
- Uses `ctp-mauve` / `ctp-pink` instead of the aurora palette the spec calls out
- Substitutes `period` enum for the spec's `year` selector (drops "all calendar years back to signup")
- Weakest test coverage (2 files, no lib unit test)
