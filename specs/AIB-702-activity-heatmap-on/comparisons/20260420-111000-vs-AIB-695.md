## Implementation Choices Analysis

### [Spec] FR-003 Violet aurora gradient
| Ticket | Approach |
|--------|----------|
| AIB-702 | Defines `aurora-cell-{0..3}` utilities in `globals.css` with sapphire→mauve linear gradients + glow shadows |
| AIB-695 | Uses `bg-ctp-mauve/{opacity}` single-color tint; no gradient or aurora glow |

**Best**: AIB-702 — matches the aurora theme convention used across the rest of the app.

### [Spec] FR-005 Header counter format
| Ticket | Approach |
|--------|----------|
| AIB-702 | Two separate labels: "X Jobs" / "Y Shipped" (visually split) |
| AIB-695 | Exact spec phrasing: `"{totalJobs} jobs · {totalTicketsShipped} tickets shipped in the last year"` |

**Best**: AIB-695 — delivers the literal spec text.

### [Spec] FR-009 Hide agent filter if ≤1 agent
| Ticket | Approach |
|--------|----------|
| AIB-702 | Filter always rendered regardless of distinct agent count |
| AIB-695 | `showAgentFilter = availableAgents.length > 1` guard |

**Best**: AIB-695.

### Decision Point: State management strategy
| Ticket | Approach | CLAUDE.md Alignment | Trade-offs |
|--------|----------|---------------------|------------|
| AIB-702 | Async Server Component, no client fetching | Partial (skips TanStack Query) | Zero loading flash, no auto-refresh |
| AIB-695 | Server-seeded + TanStack Query (60s refetch) | Yes (TanStack Query convention) | Live updates, extra client JS |

**Best**: AIB-695 — follows the stated state-management convention (`TanStack Query v5.95.2, client-side polling`).

### Decision Point: Type safety / contract
| Ticket | Approach |
|--------|----------|
| AIB-702 | Zod schemas in `lib/types/activity.ts`; schema used in integration tests for response validation |
| AIB-695 | Plain TS interfaces inside `lib/db/activity.ts`; no runtime validation |

**Best**: AIB-702.

### Decision Point: Agent filter in DB vs JS
| Ticket | Approach |
|--------|----------|
| AIB-702 | Pushes filter into Prisma query (`ticket: { OR: [{ agent }, { agent: null, project: { defaultAgent: agent } }] }`) — DB-side scoping |
| AIB-695 | Fetches all jobs, resolves effective agent in JS via `resolveEffectiveAgent`, then filters in memory |

**Best**: AIB-702 — scales better; avoids pulling every job into memory when filtered.

## Ranking & Recommendation

### 1. AIB-702 — 82%
**Why it wins**:
- 2× the test coverage (unit + integration aggregation + integration API + e2e)
- Zod-validated response contract
- True aurora gradient cells (`aurora-cell-0..3`) matching app theme
- DB-side agent filtering (no in-memory scan of all jobs)
- Updated `CLAUDE.md` with new Activity data section

### 2. AIB-695 — 81%
**Why it lost**:
- Only 2 test files, no e2e
- No Zod / runtime validation
- Single-color mauve cells miss the "violet aurora gradient" intent
- Always renders agent filter (violates FR-009 with 0/1 agents)
- Effective-agent resolution done in JS after loading all jobs

**Where AIB-695 is better**:
- Literal FR-005 header copy
- FR-009 hide-filter-when-≤1 guard
- TanStack Query state pattern matches project convention
- Truly "chipped" (omitted) corner cells vs dimmed
